# HQ SR candidates for 1.2

Date: 2026-11-03. Neither candidate is distributed or selected by Auto. These are
conversion and tile-consistency results, not a completed 1.2 quality evaluation.

## Sources and conversion

Both models are by Philip Hofmann (Helaman). `convert_community_sr.py` pins the
original checkpoint URLs and full SHA-256 values. The WebPhoto weights are
CC-BY-4.0; the public x2 release explicitly licenses its weights under Apache-2.0.
Sources and attribution are recorded in [MODELS.md](../../MODELS.md).

The existing Spandrel 0.4.1 loader recognizes both checkpoints. Two export
adapters preserve the original forward pass without changing weights:

- RealPLKSR's channel `repeat_interleave`, unsupported by pnnx, becomes static
  concatenation of the same RGB planes in the same order.
- DySample's dynamic `arange`/`meshgrid` becomes cumulative sums of ones. Negative
  axes preserve the spatial axis when ncnn removes the batch dimension. Each of
  the four groups uses a batch-one `GridSample`, preserving ncnn's batch-one
  contract. Coordinates remain dynamic, including the width/height normalizer.

The adapter must match the upstream forward pass exactly before tracing. The
exported graph then passes TEST-ML-001 at 96×96 and an unseen 71×103 input. Tests
also compare the DySample adapter to upstream at rectangular and one-pixel-wide
inputs, and reject non-finite outputs/references before clamping.

| Candidate | Python ncnn 96×96 PSNR | Python ncnn 71×103 PSNR | Native golden 96×96 PSNR |
|---|---:|---:|---:|
| `sr.webphoto-realplksr` | 124.85 dB | 126.24 dB | 119.37 dB |
| `sr.public-realplksr-x2` | 98.20 dB | 129.41 dB | 99.26 dB |

Both use fp32 weights. Differences between the two golden columns reflect
different deterministic inputs and native CPU kernels. All values pass the
40 dB conversion gate. Provenance and output hashes:

- [WebPhoto](hq-sr/sr.webphoto-realplksr.json)
- [Public x2](hq-sr/sr.public-realplksr-x2.json)

Environment: PyTorch 2.14.1, pnnx 20260526, Python ncnn 1.0.20260526; native ncnn
`5a0288f255daa6c3294f77109f67718e434ec020`, GCC Release, runtime CPU dispatch off.
Native `test_golden` completed 26 checks with no failures, including the bundled
reference and byte-identical repeated output. The host was an Intel i5-12400;
this is not T2 phone performance evidence. Models are loaded on the CPU for these
checks; Vulkan GridSample remains unimplemented in the pinned ncnn dependency.

## Tile consistency smoke test

The top-left 384×384 crop of SHA-256-pinned Kodak image 1 was processed by the
application's `refocal-cli`, CPU, four requested threads, sharpening 1.0, pad 64,
with tiles 128 and 256. Each output was compared with a single-tile run at the
model's native scale, using the evaluator's luma PSNR. No tile/backend fallback
was allowed. Both requested sizes actually cross boundaries.

This is one image, sufficient to expose a failure but insufficient to qualify a
pack. Full evidence still needs all golden categories and the T2 device gate.
Raw measurements: [seams.json](hq-sr/seams.json).

| Candidate | Tile 128 | Tile 256 | 45 dB smoke gate |
|---|---:|---:|---|
| `sr.webphoto-realplksr` | 38.51 dB | 41.54 dB | Fail |
| `sr.public-realplksr-x2` | 69.56 dB | 73.44 dB | Pass on this image |

WebPhoto fails the 45 dB seam gate at both sizes (38.51 dB and 41.54 dB). Its
GroupNorm depends on the image area presented to each tile. `split_tiles=false`
prevents OOM subdivision from silently changing those statistics, but does not
make ordinary tiling equivalent to whole-image inference. Before admission it
needs a validated global-statistics/context strategy as described by roadmap
13 §1.2. Pad 64 is an experimental setting, not an approved pack recipe.

## Reproduction

Use the offline Python dependencies documented by the converter, including
Spandrel 0.4.1 and pnnx/ncnn 20260526. From the repository root:

```sh
python tools/models/convert_community_sr.py /tmp/hq-models \
  --weights /tmp/hq-weights --pnnx /path/to/pnnx --only sr.webphoto-realplksr
python tools/models/convert_community_sr.py /tmp/hq-models \
  --weights /tmp/hq-weights --pnnx /path/to/pnnx --only sr.public-realplksr-x2
```

The usual `test_golden` additionally needs the bundled model and its golden
pair (`tools/models/fetch.sh`, `tools/models/golden.lock`). For the full 1.2
comparison, fetch `sr.x4plus`, build `refocal-cli`, and run:

```sh
python tools/models/fetch_pack.py sr.x4plus /tmp/hq-models
python tools/ml/sr_eval.py /tmp/hq-eval --cli native/build/refocal-cli \
  --models /tmp/hq-models --model sr.webphoto-realplksr --baseline sr.x4plus
# The public candidate needs its native scale:
python tools/ml/sr_eval.py /tmp/hq-eval-x2 --cli native/build/refocal-cli \
  --models /tmp/hq-models --model sr.public-realplksr-x2 --scale 2 --baseline sr.x4plus
```

`eval.yml` exposes both candidates and automatically fetches/selects the x4plus
baseline and the public candidate's x2 scale. `--synthetic-only` can reject a
candidate but never qualify one. Full NR-IQA and a 1 MP → 4x
comparison of WebPhoto against x4plus on the T2 phone remain outstanding. The
public candidate also needs device evaluation at its native 2x scale. No manifest, model
download offer, or Auto choice changes are justified by these results.

## Follow-up: shared GroupNorm context (2026-11-05)

The reduced-image normalization strategy in roadmap 13 §1.2 now has an isolated,
reproducible experiment: `tools/ml/webphoto_context_eval.py`. It verifies the
checkpoint SHA-256 before loading, records the input hash, and uses the same
384×384 Kodak 1 crop, reflect-101 halo of 64 and tile ownership as the native
pipeline. This experiment runs the original fp32 PyTorch model without sharpening.
It checks both agreement between tiles and drift from the original whole-image
model. Raw evidence: [webphoto-context.json](hq-sr/webphoto-context.json).

Each GroupNorm's statistics are captured from its own input during an unchanged
forward pass, then shared by all tiles as a channel-wise affine transform.
The 192×192 context is area-downsampled. The 384×384 context is an oracle using
the full image, including its reflected halo. Neither changes the trained weights.

| Context | Tile 128 vs shared-context whole | Tile 256 vs shared-context whole | Shared-context whole vs original whole |
|---|---:|---:|---:|
| Reduced, 192×192 | 102.41 dB | 104.32 dB | 30.13 dB |
| Full-image oracle, 384×384 | 100.95 dB | 103.28 dB | 100.36 dB |

Shared statistics remove the tile discrepancy on this image. However, the reduced
context changes the result substantially: 30.13 dB against the original whole
model, below the 40 dB conversion-equivalence gate. Such a variant would need its
own quality evaluation. The oracle confirms the cause but requires a full-image
model pass to obtain statistics, so it does not solve the bounded-memory mobile
implementation. No shared-statistics path is added to the application.

Reproduce after fetching Kodak 1 with `sr_eval.py`:

```sh
python tools/ml/webphoto_context_eval.py \
  /tmp/hq-weights/sr.webphoto-realplksr.pth \
  /tmp/hq-eval/src/kodim01.png /tmp/webphoto-context
```

## Follow-up: evaluation safeguards and native checks

`--quick` cannot qualify a candidate, even when its sampled metrics pass. The
report rejects missing or non-finite synthetic metrics and every non-finite seam
measurement, including a NaN that `min()` can hide behind another finite sample.
Starting a new run clears old reports so a failed rerun cannot retain an earlier
qualification as its apparent result.
Kodak downloads now retry transport errors with a finite timeout, verify the
SHA-256 before atomic publication, and remove partial files after failure.

`--seams-only` runs all four seam inputs independently of the synthetic/NR-IQA
comparison and persists each completed measurement. Its exit code describes
only this diagnostic; `sr.json` always records `qualified: false` for that scope:

```sh
python tools/ml/sr_eval.py /tmp/hq-seams --cli native/build/refocal-cli \
  --models /tmp/hq-models --model sr.public-realplksr-x2 \
  --baseline sr.public-realplksr-x2 --scale 2 --seams-only
```

Public x2 passed all eight native seam checks on Kodak 1–4 at its native 2x
scale. The minimum was 69.53 dB, above the 45 dB diagnostic threshold.
The run uses the application's sharpening at 1.0 and forbids tile/backend
fallbacks. Raw results, source hashes and model hashes:
[public-x2-seams.json](hq-sr/public-x2-seams.json). This verifies these four
inputs; it does not establish quality on the full golden set or on a phone.

The native golden suite was rerun on the i5-12400 with CPU runtime dispatch
enabled: 30 checks, zero failures, including byte-identical repeated output.
Conversion agreement was 123.45 dB for WebPhoto and 99.22 dB for Public x2.
These are host correctness checks; they provide no phone performance evidence.

A synthetic exploration reached Kodak 1, covering clean, blur, noise
and JPEG at 2x against `sr.x4plus`. Its measurements are preserved in
[public-x2-smoke.json](hq-sr/public-x2-smoke.json). One image cannot qualify a
category or establish a quality win. The complete 24-image synthetic comparison,
full NR-IQA and manual review remain outstanding, along with the physical-device
gates. Neither candidate is admitted to the manifest or Auto.
The exploratory run ended on a transport error while fetching the next input;
its completed measurements are retained separately from qualification evidence.
