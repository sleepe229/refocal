# Security review before 1.0

| | |
|---|---|
| Date | 2026-10-17 |
| Version | `main` after 0.5.0-beta.1 |
| Scope | Android app: exported components, intents, content providers, model download and verification, `.rfpack` reader, native hardening, logs and backup, CI supply chain |
| Method | Code reading against the threat model ([09 §2](../spec/09-security.md)), checks of the release APK (`v0.5.0-beta.1`) |
| Not covered | iOS (not built yet); the inference library's model parser beyond fuzzing (T6, see below); an external audit |

## Findings

| # | Area | Finding | Severity | Status |
|---|---|---|---|---|
| 1 | Share / "Edit with" intents | The URI comes from the sending app, and Refocal read it with its own rights: `file:///data/data/io.github.refocal.app/...` or a URI of Refocal's own `ShareProvider` would put a private file (history previews, other images in `cache/share`) into the editor, from where the user could save or share it. | Medium | Fixed: only `content://` URIs of other apps' providers are taken |
| 2 | Share / pick | The copy into the inbox had no size limit; the core refuses files over 200 MB (SEC-INP-002) only after the copy, so a large stream filled the disk first. | Low | Fixed: the copy stops at 200 MB |
| 3 | Model download | The manifest, its signature and license texts were downloaded without a size limit, and a model file was not cut off past its declared size. A bad mirror could fill the disk. Integrity was not affected: signature and SHA-256 are checked afterwards. | Low | Fixed: 1 MB / 4 KB / 1 MB / declared size |
| 4 | Model download | Only the first URL had to be `https`; `dart:io` followed redirects to `http://`, so a request could leave in clear text (PRIV-NET-004). | Low | Fixed: redirects followed by hand, each hop `https` |
| 5 | Native build | Hardening (SEC-INP-003) came only from NDK defaults, with no check. The release library has all of it. | Info | CI check added (`tools/security/check_elf.py`) |

## Checked, no finding

- **Exported components.** Only `MainActivity` (launcher, `SEND`/`SEND_MULTIPLE`/`EDIT` of `image/*`). Deep links are off (`flutter_deeplinking_enabled=false`), so intent data never becomes a route. `ProcessingService` and `ShareProvider` are not exported.
- **`ShareProvider`.** Read-only. Paths are canonicalized and must be directly in `cache/share/`. Other apps get access only through the URI grant of a share intent.
- **`openUrl`.** Opens `https` URLs only.
- **`.rfpack` reader** (`native/core/src/util/zip.cpp`, T5).
  - Names are allow-listed (no `/`, `..`, absolute paths), and duplicates are refused.
  - Refused outright: ZIP64, encryption, multi-disk archives, symlinks and directories.
  - Limits on entry count, total size and compression ratio, and overlapping entries are refused.
  - CRC and size are checked while unpacking, and the signature is checked before anything is parsed.
  - Fuzzed (`fuzz_zip`).
- **Manifest** (T1–T3). The minisign signature is checked before parsing, with two keys for rotation. The serial must not go back (rollback). Each file is checked by SHA-256 before activation; license texts are checked against the manifest too.
- **Images** (T4, T11). Size limits are checked on the header, before decoding. The decoders and `metaio` are fuzzed in CI (5 min per PR, 1 h nightly). The 24 h gate is `fuzz-ga.yml`.
- **Logs and backup** (T7).
  - The core redacts paths and URIs from the log, and the log leaves the device only when the user exports it.
  - Cloud backup and device transfer include `prefs.sqlite` only.
  - GPS is removed from results by default (T8).
- **CI supply chain** (T9, T10).
  - Every action is pinned by commit SHA, and Dependabot plus a nightly OSV scan cover dependencies.
  - Commits are DCO-signed.
  - The release key exists only in the release job's secrets, and the APK is reproducible (S8, F-Droid's check).

## Open

- **T6, malicious model.** Packs are signed, so this needs a signed malicious model (or a key compromise). ncnn's model parser is not fuzzed by us; CVE-2026-50144 was fixed by updating ncnn. Fuzzing ncnn's `.param`/`.bin` loader is a candidate for 1.1.
- **External review.** This is the maintainers' review. An independent audit is recommended once the project has the means.
