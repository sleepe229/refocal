## 1. Итог в трёх пунктах

1. **Оригинальный GFPGAN непригоден для мобильного fp16.** В декодере StyleGAN2 промежуточные значения `s²` и `Σ W²·s²` достигают 10⁶ при пределе fp16 65504. Получается `rsqrt(inf) = 0`, и выход тихо обнуляется: PSNR 9 дБ, NaN нет. Это свойство модели, а не рантайма: в чистом fp16 на CUDA результат тот же. Ломаются любые fp16-рантаймы: ncnn Vulkan, ARM CPU fp16, Core ML/ANE.
2. **Модуляция весов во время инференса (23 свёртки с `dynamic_weight`) не поддерживается быстрыми путями:** ncnn Vulkan уводит их на CPU, на ANE их тоже нет. Отсюда ×22 медленнее на RTX 3060 и лишние ~1.4 ГБ памяти.
3. **Обе проблемы решены математически эквивалентной перезаписью** модулированной свёртки (§3). Выход отличается от оригинала на ≤ 2·10⁻⁵ в fp32. После неё ncnn Vulkan fp16 проходит гейт ТЗ (PSNR ≥ 48.8 дБ при пороге 35), а Core ML конвертируется без свёрток с динамическими весами.

## 2. Условия

- **Модель:** GFPGAN v1.4, архитектура `GFPGANv1Clean`. Код TencentARC/GFPGAN v1.3.8 (`2eac203`), веса `GFPGANv1.4.pth` (SHA-256 `e2cd4703…be5ad`), 86.44M параметров, **398 GFLOPs** на лицо 512×512.
- **Данные:**
  - 6 портретов из общественного достояния (Wikimedia Commons): Линкольн, Лавлейс (живопись), Эйнштейн, Дуглас, Кюри, Сольвеевский конгресс 1927.
  - 9 лиц × 2 варианта: оригинальное выравнивание и синтетическое низкое качество (лицо ~96 px + JPEG q35).
  - Детекция YuNet на копии 640 px, выравнивание по шаблону FFHQ-512.
- **Машина:** x86-64, 12 потоков, 30 ГБ RAM; GPU NVIDIA RTX 3060 и **Intel UHD 730** (встроенная, ближайший прокси мобильного GPU).
- **Версии:** torch 2.14.1, onnx 1.23.2, onnxruntime 1.31.0, ncnn/pnnx 20260526, coremltools 9.0 (полный список — `requirements.lock`).
- **Эталон:** PyTorch fp32 оригинальной модели. Метрики считаются на 8-битном RGB.
- **Замер:** медиана 3 прогонов после прогрева, 8 потоков CPU. Каждый бэкенд в отдельном процессе, пиковый RSS по `ru_maxrss`.

## 3. Модификация графа (обязательна для мобильных)

Оригинальная модулированная свёртка StyleGAN2:

```
W' = W · s                          # веса на каждый вход (dynamic weight)
W' = W' · rsqrt(Σ_{i,k} W'² + ε)    # демодуляция
y  = conv(x, W')
```

Эквивалент для batch = 1 (формулировка из статьи StyleGAN2):

```
s  = s / max|s|                     # fp16-безопасность: демодуляция инвариантна к масштабу s
y  = conv(x · s, W) · rsqrt(Wsq · s² + ε),   где Wsq[o,i] = Σ_k W[o,i,k]²  (константа)
```

- Веса свёртки статические, и это обычный `Conv`: работает на Vulkan, ANE, CPU-winograd.
- `s ∈ [-1, 1]`, поэтому `s² ≤ 1`, а `Wsq·s²` и `x·s` остаются в диапазоне fp16.
- Поканальное масштабирование коммутирует с билинейным ресемплингом, поэтому умножается после up/downsample.
- Реализация: `_static_modconv_forward` в `gfpgan_model.py`, около 20 строк. Применяется при загрузке модели и не требует переобучения.

- Визуально эталон и ncnn Vulkan fp16 неотличимы: `spikes/s1-gfpgan/out/compare_montage.jpg` (не в репозитории, воспроизводится скриптом).

### Размеры артефактов

| Формат | Оригинал | Перезапись |
|---|---|---|
| ONNX fp32 | 340 МБ | 351 МБ |
| ncnn (fp16-хранение) | 219 МБ (62 MemoryData в fp32) | **177 МБ** |
| Core ML mlprogram fp16 | — | **176 МБ** |

### Конверсия

- **ncnn:** `pnnx` из TorchScript для перезаписанной модели падает с повреждением кучи (`free(): invalid next size`, pass_level4). Через ONNX (`pnnx model.onnx`) всё проходит. Решение: конвейер ML-CNV идёт через ONNX.
- **Core ML:** `coremltools 9.0` + torch 2.14 (официально проверен до 2.7) — конверсия проходит за 5 с. 95 `conv`, все веса константные, операции стандартные (`conv`, `leaky_relu`, `upsample_bilinear`, `linear`, `reduce_max`, `rsqrt`). Выполнение на ANE и паритет проверяются только на macOS/iOS (S1b).

### Память CPU-пути (ncnn, x86, fp32)

| Настройка | После загрузки | Пик после прогона |
|---|---|---|
| по умолчанию (winograd + sgemm) | 895 МБ | 2.2–3.9 ГБ |
| без winograd/sgemm | 454 МБ | 1.3–2.4 ГБ |
| без winograd/sgemm, fp16-хранение весов | 390 МБ | 1.2–1.4 ГБ |

- **Веса.** Winograd и sgemm хранят расширенные копии ядер 3×3 (до ×7), это основная статья при загрузке.
- **Активации.** Около 0.8 ГБ в fp32: GFPGAN заранее вычисляет SFT-условия для всех разрешений и держит их до конца декодера. На ARM в fp16 — около 0.4 ГБ.
- **Рост RSS между прогонами** (+200 МБ) — кэш пул-аллокатора ncnn. В native core нужен собственный аллокатор с явным освобождением после стадии (ADR-0012: модель выгружается после стадии лиц).

## 5. Мобильные устройства (оценка → S1b)

Замер на телефонах не проводился: устройства не подключены. Оценка опирается на 398 GFLOPs и измеренную эффективность ncnn Vulkan fp16 на Intel UHD 730: ~0.37 TFLOPS эффективно, это ~35–40% от пика.

| Тир | Устройство (пример) | Бэкенд | Оценка, с/лицо | NFR-PERF-003 |
|---|---|---|---|---|
| T2 | Snapdragon 8 Gen 2/3 (Adreno 740/750) | Vulkan fp16 | 0.25–0.4 | ≤ 1 с ✅ |
| T2 | iPhone 15 Pro (A17 Pro) | Core ML ANE | 0.15–0.4 | ≤ 1 с ✅ |
| T1 | Exynos 1380 (Mali-G68), Dimensity 1080 | Vulkan fp16 | 0.8–1.5 | ≤ 3 с ✅ |
| T1 | iPhone 12 (A14) | Core ML ANE | 0.4–0.8 | ≤ 3 с ✅ |
| T0 | Mali-G52 MC2 / PowerVR GE8320 | Vulkan fp16 (если драйвер исправен) | 4–8 | ≤ 10 с ⚠️ |
| T0 | 4×Cortex-A55 | CPU fp16 | 10–15 | ≤ 10 с ❌ |

**Память на устройстве** (оценка): веса fp16 177 МБ + активации fp16 ~0.4 ГБ ≈ **0.6 ГБ**. Это укладывается в бюджет T1 (1.0 ГБ), но не T0 (600 МБ). На iOS и Android GPU-аллокации входят в footprint процесса (единая память).

## 6. Наблюдения о качестве (для [15](../spec/15-ethics-responsible-ai.md))

- На размытом лице из Сольвеевского конгресса модель **дорисовала очки**: на входе их разглядеть нельзя.
- Живописный портрет Ады Лавлейс превращается в «фотографию», стиль меняется.
- Это подтверждает требования FR-FACE-004/009/010: умеренная сила по умолчанию, ослабление на крупных лицах, предупреждение. Эти примеры стоит включить в golden-набор как категорию «галлюцинации».
