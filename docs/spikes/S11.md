# S11 — Community SR candidates for 1.1

Date: 2026-10-30. Baseline: `sr.general-x4v3` (the bundled DNI 0.5 model).

## Decision

Ship 1.1 without a new SR pack. All four tested variants exceed the mandatory
0.3 dB synthetic PSNR loss limit in `sr_eval.py`. Existing models and Auto's
selection remain unchanged, as allowed by roadmap 13 §1.1 and ADR-0026.

This is a rejection at a required gate, not a claim that the candidates look
worse on every real photo. SPAN medium improves clean and JPEG synthetic scores,
but loses on blur and noise. No category is approved for Auto by this experiment.

## Inputs and reproducibility

- All models are by **Helaman**, under **CC-BY-4.0**, as recorded by OpenModelDB.
  Source links and upstream SHA-256 pins are in
  [`convert_community_sr.py`](../../tools/models/convert_community_sr.py).
- The synthetic set is all 24 SHA-256-pinned Kodak images, downsampled by the
  candidate's native scale with clean, blur, noise and JPEG degradations.
  Each candidate and baseline use the same input, output scale, and sharpening.
  The native x2 candidate is compared against the baseline at 2x, not 4x.
- Both plain and effective-resolution requests were measured (ADR-0025). An
  effective-resolution row is omitted when its request equals the plain one.
- The SR real-photo set contains 46 attributed, pinned photos; together with
  Kodak this is 70 inputs. DIV2K is excluded because its licence is research-only
  (04 §7.2). Downloaded real photos were verified, but **full NR-IQA was stopped
  after all candidates failed the mandatory synthetic gate**. Partial real-photo
  results are not used for a release decision. No MUSIQ/CLIP-IQA/MANIQA win is claimed.
- CPU inference through the application's `refocal-cli`, Release build, GCC,
  `ENH_NCNN_RUNTIME_CPU=OFF`, four inference threads. Jobs ran concurrently on a
  shared host; timings are diagnostic and are not device performance evidence.
- Conversion: PyTorch 2.14.1, Spandrel 0.4.1, pnnx 20260526. Both the Python ncnn
  conversion check and the application's native `test_golden` were used.

```sh
python tools/models/convert_community_sr.py /tmp/s11/models \
  --weights /tmp/s11/weights --pnnx /path/to/pnnx
# Put the bundled model and its pinned golden pair in that model directory too:
DEST=/tmp/s11/models tools/models/fetch.sh
LOCK=tools/models/golden.lock DEST=/tmp/s11/models tools/models/fetch.sh
cmake -S native -B native/build-s11 -DENH_BUILD_CLI=ON -DENH_BUILD_TESTS=ON \
  -DENH_NCNN_RUNTIME_CPU=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build native/build-s11 -j --target refocal-cli test_golden
native/build-s11/test_golden /tmp/s11/models
python tools/ml/sr_eval.py /tmp/s11/lsdir --cli native/build-s11/refocal-cli \
  --models /tmp/s11/models --model sr.lsdir-compact --synthetic-only
# Repeat for sr.nomos-span-medium / sr.nomos-span-strong.
# For sr.nomos-compact-x2 also pass --scale 2.
```

The evaluator requires numpy, scipy and Pillow; conversion also needs torch,
Spandrel, pnnx and ncnn. A full evaluation additionally needs pyiqa 0.1.16.
`--synthetic-only` deliberately returns failure for a candidate: a run without
NR-IQA can reject a pack but cannot qualify it. For a full CI run, dispatch
`eval.yml` with `category=sr` and the `community_model` choice. Set
`args=--synthetic-only` to reproduce this rejection gate.

## Conversion parity

`test_golden` on the application's ncnn, clamped RGB against PyTorch fp32:

| Candidate | Weight storage | PSNR dB | TEST-ML-001 ≥ 40 dB |
|---|---|---:|---|
| LSDIR Compact R3 | fp16 | 55.08 | Pass |
| NomosUni Compact medium | fp16 | 55.74 | Pass |
| Nomos8k SPAN medium | fp32 | 82.00 | Pass |
| Nomos8k SPAN strong | fp32 | 76.21 | Pass |

SPAN's fused Conv3XC weights lose too much precision in fp16: the initial checks
measured 28.95 dB (medium) and 22.28 dB (strong). The same trace with fp32 weights
passes; the synthetic comparison therefore uses the faithful fp32 conversion.
No lower threshold or weakened reference is used. The converter also verifies
a rectangular input shape absent from tracing.

## Tile checks and artifacts

Seam checks use 384×384 natural crops from Kodak 1–4, comparing tiles 128 and 256
with a single tile. Unlike the old downsampled inputs (at most 192 px at x4),
these crops actually cross boundaries at **both** requested tile sizes. Tile or
backend fallback makes the seam run fail rather than silently changing the test.

Raw per-image PSNR/SSIM, seam scores and conversion provenance:

- [Nomos8k SPAN strong](../ml/s11/sr.nomos-span-strong.json)

The evaluator's release status now rejects a candidate when every real-photo
category loses two NR metrics, when evidence is missing/non-finite, or when
NR-IQA was disabled. Previously NR losses were printed but did not affect its
exit code. Regression tests cover these decisions.
