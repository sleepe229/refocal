## 1. Итог в трёх пунктах

1. **Проверка корректности ловит «тихий мусор».** Оригинальный GFPGAN в fp16 на RTX 3060 и Intel UHD 730 даёт PSNR 10.09 дБ без единого NaN. Проба помечает его `wrong_output`. Пара «драйвер + модель» уходит в локальный blocklist с действием `gpu_fp32`, и следующий запуск считает лицо в Vulkan fp32 (57.1 дБ). Все 6 синтетических порч тоже пойманы. Безобидный сдвиг на 2 уровня из 255 правильно пропущен (41.8 дБ).
2. **Crash sentinel работает на настоящих падениях.** Процесс действительно умирает через `abort()`/SIGSEGV посреди Vulkan-стадии. E2E-тест проверяет обе политики: строгую ADR-0016 (CPU с 3-го старта) и предлагаемую (CPU уже со 2-го старта, навсегда после 2-го падения подряд). Также проверены исходы `os_kill` и `native_crash` из ApplicationExitInfo: 20/20 проверок. В самой пробе каждый бэкенд работает в дочернем процессе, поэтому падение драйвера становится статусом `crash`, а проба не умирает.
3. **Пороги тиров привязаны к NFR-PERF-001 и откалиброваны прогоном 1 МП.** Время одного тайла 128 × 108 тайлов точно предсказывает время инференса 1 МП: 14.4 с у Intel UHD 730 при 133.5 мс на тайл. Предлагаемые пороги compact SR на тайле 128: **T2 ≤ 25 мс, T1 ≤ 80 мс, T0 ≤ 280 мс**. По ним Intel UHD 730 (ближайший прокси Mali-G68 из S1) получает T0: 1 МП 4× занимает 12.4–14.4 с одного инференса и не укладывается в T1 ≤ 12 с. Это сигнал пересмотреть NFR-PERF-001 для T1 (§8).

## 2. Условия

- **Машина:** x86-64 Intel i5-12400 (6 ядер / 12 потоков), 30 ГБ RAM, Linux 7.0. Машина общая со спайком S2: каждый замер запускался под `flock /tmp/claude-1000/refocal-bench.lock`.
- **Vulkan-устройства** (по данным пробы):

- **Время тайла 128 из микробенчмарка × 108 предсказывает 1 МП с точностью ≈ 10 % (UHD 730: 133.5 × 108 = 14.4 с; CPU: 108 против 117 мс).** Поэтому пороги задаются в «мс на тайл 128» (§6).
- Тайл 256 вместо 128 выигрывает лишь 0–14 %, а на RTX даже проигрывает. Накладные расходы паддинга (×1.78 против ×1.31) почти компенсируются плохой загрузкой GPU на мелких диспатчах.

### 3.4 Время самого микробенчмарка (NFR-PERF-009)

- На один бэкенд: 1 прогрев + 5 прогонов тайла 160 + 6 прогонов тайла 128 + создание Vulkan-инстанса и загрузка. Получается 0.7 с (RTX), 2.2 с (UHD 730 fp16) и 1.9 с (CPU).
- «Телефонный» набор (GPU fp16 + CPU) на UHD-классе укладывается в ≈ 4 с, это внутри бюджета T0 ≤ 15 с.
- Медленный драйвер без защиты съедает бюджет целиком: только llvmpipe fp16 занял 19–22 с. Отсюда защита `--max-run-ms`: если прогрев медленнее порога, бэкенд получает статус `too_slow` без серии замеров. С порогом 1 с llvmpipe fp16 занял 2.4 с вместо 19 с, корректность выхода всё равно проверена.
- Компиляция пайплайнов GFPGAN на RTX занимает 2.5–6 с при первом запуске. Для бенчмарка лиц это аргумент за кэш пайплайнов (NFR-PERF-022) и за запуск только после установки пака.

## 5. Решения по blocklist

### 5.1 Формат

Схема из manifest.schema.json сохранена, все добавления опциональны.

| Решение | Почему |
|---|---|
| `device_regex` — ECMAScript, **полное совпадение**, без учёта регистра | Пример из 05 §11 (`Mali-G52.*`) подразумевает полное совпадение. Без явного `.*` правило `Mali-G52` не заденет `Mali-G52 MC2`, это проверено тестом. Битый regex отбрасывает только своё правило |
| `driver_min`/`driver_max` — включительно, **сравнение по префиксу** | `"r26"` покрывает все r26pX, `"580"` — все 580.x. Так правила пишутся естественно |
| Версия драйвера декодируется **с учётом вендора** | У NVIDIA своя упаковка: тот же raw по стандартной формуле даёт 145.380.320 вместо 580.95.05 |
| `os_min`/`os_max`: Android — API level, iOS — версия | Номер релиза Android на прошивках неоднозначен, API level — нет. Если версия ОС неизвестна, ограниченное по ОС правило не применяется |
| `models` — glob по `<pack id>@<версия>` | `face.*` работает как раньше, а `face.gfpgan-1.4@1.0.*` позволяет закрыть конкретную версию пака. Исправленная модель не наследует старые блокировки |
| Новое действие `gpu_fp32` | Типичный дефект мобильного GPU — переполнение fp16 (S1). Vulkan fp32 тогда в 2 раза быстрее CPU (0.81 с против 1.67 с на лицо). Приоритет: `disable` > `cpu` > `gpu_fp32` |
| Новые поля `id`, `platform`, `api_max`, `gpu_blocklist_revoke` | `id` нужен для телеметрии и отзыва. `api_max` — по нему ncnn сам ведёт таблицу багов (Adreno < 1.0.66, Mali < 1.0.82). Отзыв позволяет снять ложное встроенное правило через манифест без релиза. Локальные правила удалённо не отзываются |
| Неизвестные поля — предупреждение, правило принимается | Совместимость вперёд: старое приложение читает новый манифест. Сейчас схема запрещает это через `additionalProperties: false`, для манифеста это вредно |
| Слияние — объединение источников, сильнейшее действие побеждает | Встроенный + манифест + локальный. Порядок источников не важен |
| Локальное правило (sentinel/бенчмарк) фиксирует точную версию драйвера (`driver_min == driver_max`) | Обновление драйвера снимает блокировку автоматически |

### 5.2 Кодирование `driverVersion` по вендорам

| Вендор | Упаковка | Читаемо | Проверено |
|---|---|---|---|

| Mesa (Intel ANV, llvmpipe; также RADV, Turnip, Panfrost) | `VK_MAKE_VERSION` 10.10.12 | 26.0.8 = версия Mesa | ✅ |

### 5.3 Встроенный стартовый список

- `llvmpipe.*` и `SwiftShader.*` → `cpu`. Измерено: на том же CPU это в 2 раза медленнее ncnn CPU в fp32 и в 13 раз в fp16, а бенчмарк одного llvmpipe fp16 занимает 20+ с.
- Правила `Mali-G52 ≤ r26p0 face.*` и `PowerVR.* *` взяты из примера 05 §11 и **не подтверждены**. Они помечены `unverified` и до S3b подтверждаются или удаляются.
- Независимо от blocklist выбирается **самый быстрый исправный** бэкенд, а не «GPU по умолчанию». Медленный GPU (llvmpipe, слабые PowerVR) проигрывает CPU автоматически.

## 6. Пороги тиров (предложение)

Вывод из NFR-PERF-001 (1 МП → 4×, compact, без лиц: T0 40 с, T1 12 с, T2 4 с). 1 МП на тайле 128 с паддингом 16 — это 108 тайлов. Время ≈ 108 × t₁₂₈ × k, где k ≈ 1.3 — pre/post из 05 §3; S2 уточнит k для конвейера с перекрытием.

| Порог | Формула | Предложение |
|---|---|---|
| T2_THRESHOLD (`gpu_tile128_ms`) | 4000 / (108 × 1.3) = 28 | **25 мс** |
| T1 (новый) | 12000 / 140 = 85 | **80 мс** |
| «400 мс» для CPU → T0 | 40000 / 140 = 285 | **280 мс**. Медленнее — T0 с предупреждением «NFR-PERF-001 не выполняется» |
| RAM T0 | MemTotal у «4 ГБ» телефона ≈ 3.5–3.8 ГБ | **< 3.3 ГБ** по MemTotal (≈ «меньше 4 ГБ») |
| RAM T2 | MemTotal у «8 ГБ» ≈ 7.2–7.7 ГБ | **≥ 7.0 ГБ** по MemTotal |

Правило:

```
backend = fastest healthy backend (gate passed, not blocklisted)   # не "GPU first"
tier = T0 if ram < 3.3 GB or t128(backend) > 80 ms
       T2 if ram >= 7.0 GB and t128(backend) <= 25 ms
       T1 otherwise
below_t0_budget = t128(backend) > 280 ms   # предупреждение, авто 2×/только лица
SoC-таблица — только подсказка до завершения первого бенчмарка
```

Наши устройства: RTX 3060 → T2 (5 мс). UHD 730 fp16 → T0 (133 мс). CPU i5 → T0 (108 мс). llvmpipe → блок, без него T0.

Сверка с S1: по оценке S1 Mali-G68 эквивалентен UHD 730 (0.8–1.5 с на лицо при 1.07 с у UHD 730). Тогда A54/Pixel 6a получат T0, а не T1, как в device-matrix. Либо T1-устройства на деле быстрее UHD 730, либо T1-цель 12 с нереалистична. Это решает S3b на A54. Если A54 даст ≈ 130 мс/тайл, предлагается NFR-PERF-001 T1 ≤ 20 с и T1-порог 130 мс.

## 7. Что осталось (S3b — реальные устройства)

1. **Собрать под Android.** NDK на машине спайка нет, поэтому кросс-сборка не выполнялась: CMake готов, команды — в README и `tools/build_android.sh`, нужен готовый пакет `ncnn-<ver>-android-vulkan`. Нужно собрать и прогнать `test_blocklist`/`test_sentinel` на устройстве через adb.
2. **Прогнать пробу** (`--face --ignore-blocklist`) на ★-устройствах device-matrix: S23/S24 (Adreno 740/750), A54 (Mali-G68), A14/Redmi 9A (Mali-G52/PowerVR GE8320). Плюс по возможности Pixel 6a/8 Pro, Xclipse 940 и AOSP-эмулятор (SwiftShader).
3. **Подтвердить упаковку `driverVersion`** для Qualcomm, ARM, ImgTec и Samsung по `driver_version_raw` и `getprop` (§5.2). Добавить `driverInfo`.
4. **Подтвердить или удалить** правила `unverified`. Первичное наполнение blocklist по отчётам сообщества (issue-форма `perf-report.yml`).
5. **Откалибровать пороги** по времени тайла 128 на A54/S23/A14. Сверить `calib` 1 МП с S2 на тех же телефонах.
6. **Проверить sentinel на реальном падении драйвера.** Поднять `ApplicationExitInfo` (API 30+), включая REASON_CRASH_NATIVE и ANR при зависании GPU. Убедиться, что `fsync` sentinel-файла укладывается в бюджет стадии.
7. **Измерить время полного микробенчмарка** на T0-устройстве с учётом компиляции шейдеров (NFR-PERF-009 ≤ 15 с).
8. **iOS:** аналог для Core ML (`computeUnits` вместо Vulkan-бэкендов). Правила по чипу и версии iOS, ApplicationExitInfo нет — политика `unknown`.
