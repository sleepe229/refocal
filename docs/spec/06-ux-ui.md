# 06. UX/UI

## 1. Принципы UX

Образец — приложения Apple (Фото, Камера): фото главное, решение по умолчанию и есть продукт,
настройки появляются, только когда их ищут.

1. **Три тапа до результата:** выбрать → «Улучшить» (Auto) → сохранить. Auto выбран всегда, и
   для большинства фото больше ничего не нужно.
2. **Одно главное действие на экране.** Остальное — во вторичной кнопке, в меню «…» или в
   «Настроить».
3. **Фото на весь экран.** Тёмный фон, инструменты — тонкая полоса снизу, без простыни настроек
   под фото.
4. **Контроль без перегруза:** на виду — несколько режимов иконками (Auto, Лица, Старое фото,
   Масштаб), тонкие настройки — на панели «Настроить», один ползунок за раз, как Adjust в Фото.
5. **Технологию не показываем.** Модели, бэкенды, тайлы, тиры, миллисекунды, IPTC, `.rfpack`,
   версия ядра — не в основном интерфейсе (§1.1). Прозрачность — по запросу: «…» → «Подробнее».
6. **Каждую вещь говорим один раз.** Приватность и предупреждение об ИИ — в онбординге и в «О
   приложении»; предупреждение про лица — при первом использовании лиц (FR-FACE-010). Не под
   каждой кнопкой.
7. **Честный язык:** никогда «оригинал», «восстановленное фото» для результата; формулировки
   «улучшено ИИ», «интерпретация».
8. **Не теряем работу:** отмена и возврат — безопасны; прогресс восстанавливается.

### 1.1 Что пользователь не видит на основных экранах

| Сведение | Где доступно |
|---|---|
| Модель SR и лиц (Real-ESRGAN, GFPGAN, CodeFormer), бэкенд, время, тайл | Результат и История: «…» → «Подробнее» (FR-CMP-007) |
| Тир устройства, бэкенд | Настройки → «Дополнительно» (FR-SET-003) |
| Версия ядра, лицензии | «О приложении» |
| Импорт `.rfpack`, обновления моделей, подписи | Настройки → «Дополнительно» → «Модели» |
| Категории хранилища | Настройки → «Хранилище»: одна строка с общим объёмом; разбивка и очистка — внутри |
| Смена бэкенда, уменьшение тайла (результат тот же, только медленнее) | Не показывается; запись в журнале |
| Метка ИИ (IPTC) | Пишется всегда по умолчанию; переключатель — в «Дополнительно» (FR-META-005) |
| Коды ошибок | Журнал (FR-SET-007); на экране — одна человеческая фраза |

## 2. Карта экранов и маршрутов (go_router)

| Маршрут | Экран | Назначение |
|---|---|---|
| `/` | Home | Кнопка «Выбрать фото», последние результаты, вход в очередь |
| `/onboarding` | Onboarding | 2–3 экрана при первом запуске |
| `/editor/:sessionId` | Editor | Превью, режимы, параметры, «Обработать» |
| `/editor/:sessionId/result` | Result/Compare | Сравнение, экспорт, «Сообщить о проблеме» |
| `/queue` | Queue | Очередь пакетной обработки |
| `/history` | History | Рецепты и превью |
| `/models` | Models | Установленные и доступные паки |
| `/models/:packId` | Pack details | Описание, лицензия, размер, скачать/удалить |
| `/settings` | Settings | Экспорт, метаданные, производительность, хранилище, сеть, язык |
| `/settings/about` | About | Версия, лицензии, приватность, предупреждение об ИИ, исходники |
| `/import` | (deep link) | Приём из share → Editor или Queue |

На планшетах и foldable (ширина ≥ 840 dp) — двухпанельный макет: список (история/очередь) + редактор; `NavigationRail` вместо нижней навигации.

## 3. Ключевые потоки

### 3.1 Первый запуск

```
Splash → Onboarding (1: «Всё на устройстве», 2: «ИИ может менять детали», 3: «Сравнение»)
       → Home; в фоне — бенчмарк (FR-ONB-002), без блокировки UI
```

Home — кнопка «Выбрать фото» и сетка последних результатов. Без слогана, без карточек-
предложений: модель лиц предлагается, когда она нужна (§3.3, FR-ONB-003). Пакет — мультивыбор в
том же системном пикере.

### 3.2 Обработка одного фото

```
Home → [Системный пикер] → Editor: фото на весь экран, снизу полоса режимов
       (Auto · Лица · Старое фото · Масштаб; Auto выбран) и [Улучшить]
     → (опц.) [Настроить]: модель, шумоподавление, сила лиц, JPEG, осветление, царапины —
       ряд иконок, под ним один ползунок или переключатель выбранной
     → Прогресс (%, оставшееся время; Отмена/Пауза)
     → Result: сравнение (удержание — оригинал, слайдер) → [Поделиться] [Фильтр] [Сохранить] [«…»]
       «Фильтр»: лист с переключателем «Пастель» (под ним ползунок силы) и «Блики»
       «…»: Сохранить как файл, Сохранить как пресет, Сила эффекта, Подробнее,
       Сообщить о плохом результате
```

«Поделиться» отдаёт результат другому приложению в формате по умолчанию и с той же политикой
метаданных (геопозиция, отметка ИИ); это не сохранение: в галерею и историю не попадает.

Auto-объяснение (FR-ENH-007) — одна короткая строка под режимами («4× · 2 лица»), без названий
моделей.

### 3.3 Режим «Лица» без пака

Это и есть предложение модели лиц (FR-ONB-003): в момент, когда пользователь её захотел.

```
Editor → режим «Лица» → Sheet: «Нужна модель (170 МБ). Лицензия: некоммерческое использование.»
       → [Читать лицензию] → [Принять и скачать] → прогресс скачивания (можно свернуть)
       → по готовности режим доступен
```

### 3.4 Пакет

```
Home → пикер (мультивыбор) → Batch sheet: пресет, формат, автосохранение
     → Queue (список с прогрессом); Android — уведомление FGS; iOS — баннер «Обработка на паузе в фоне»
     → Итог: «Готово 28, ошибок 2» → [Показать ошибки]
```

### 3.5 Деградация и ошибки

| Ситуация | UI |
|---|---|
| Тайл уменьшен / бэкенд сменён | Ничего: результат тот же, только медленнее; событие — в журнале и в «Подробнее» |
| Стадия пропущена (лица, JPEG, царапины, осветление не удались) | Неблокирующий баннер одной фразой: «Лица не удалось улучшить» (FR-ENH-013) |
| Требуется понизить масштаб | Диалог: «Недостаточно памяти для 4×. Обработать в 2×?» [2×] [Только лица] [Отмена] |
| Вход больше лимита тира | Диалог с вариантами (FR-IMP-006) |
| Нет места | Диалог: «Нужно ещё 420 МБ свободного места» [Очистить кэш] [Отмена] |
| Ошибка | Экран ошибки: понятное сообщение без кода, [Повторить] [Сообщить]; код — в журнале |
| Предыдущий запуск упал на GPU | Ничего: CPU-режим включается молча, событие — в журнале |

## 4. Состояния экранов

Каждый экран описывает состояния: `empty`, `loading`, `content`, `progress`, `error`, `offline` (для Models). Пример для Models:

| Состояние | Отображение |
|---|---|
| empty (нет сети, нет кэша манифеста) | «Список моделей недоступен без интернета. Можно импортировать файл .rfpack» [Импорт] |
| loading | Скелетоны карточек |
| content | Карточки паков: название, размер, лицензия (бейдж NC), совместимость с тиром, статус |
| progress | Прогресс-бар, [Пауза] [Отмена] |
| error | «Не удалось проверить подпись» / «Сеть недоступна» + [Повторить] |

## 5. Компонент сравнения (CompareViewer)

- Источники: превью ≤ 2048 + пирамида тайлов 256 px результата; для оригинала — даунскейл входа + тайлы входа, масштабированные к координатам результата.
- Режимы: слайдер (вертикальная граница, перетаскивание), удержание = оригинал, кнопка «Показать оригинал» (toggle), side-by-side.
- Зум: пинч до 1:1 пикселей результата (до 4:1 с nearest), синхронный в side-by-side; двойной тап — 1:1 / вписать.
- Лупа: долгое нажатие — круг 2× под пальцем (Could).
- Рамки лиц (в Editor): тап — вкл/выкл лицо (FR-FACE-007).
- Производительность: подгрузка только видимых тайлов, LRU-кэш тайлов в пределах `imageCache` тира, 60 fps (NFR-PERF-010).

## 6. Тексты и тон

Правила:

- Подписи кнопок и режимов — 1–3 слова. Подзаголовок у переключателя — только если без него
  непонятно, что будет (не «Убрать царапины — находит и закрашивает царапины»).
- Без названий технологий и единиц ниже уровня пользователя (§1.1).
- Без оправданий и объяснений устройства системы: текст говорит, что произойдёт, а не почему так
  устроено.
- Ошибка — что случилось и что сделать, одной фразой. Без «Что-то пошло не так» и кодов.
- Пустое состояние — одна строка.
- Без «магии»: ни волшебных палочек, ни «ИИ сделает всё сам» (бренд, [appendix/brand.md](appendix/brand.md) §4).

| Ключ | RU | Примечание |
|---|---|---|
| `result.title` | «Улучшено ИИ» | Не «Восстановлено» |
| `face.firstUse.body` | «ИИ дорисовывает детали лица. Результат — интерпретация, а не точная копия. Черты могут измениться.» | FR-FACE-010 |
| `privacy.badge` | «Обработка на устройстве. Фото никуда не отправляются.» | Home, Onboarding |
| `license.nc.summary` | «Модель распространяется под некоммерческой лицензией. Используя её, вы соглашаетесь с условиями.» | |
| `marker.off.warning` | «Без отметки ИИ другие не узнают, что фото изменено. Выключить?» | FR-META-005 |

Глоссарий терминов UI — в `app/lib/l10n/glossary.md` (для переводчиков).

## 7. Визуальный дизайн

- Material 3 (Android) с адаптивными элементами Cupertino на iOS там, где ожидается нативное поведение (диалоги, share, pickers — системные).
- Компоновка — по образцу Фото Apple: редактор и результат — тёмный холст, фото во всю ширину,
  инструменты — нижняя полоса с иконками и подписями; списки и настройки — сгруппированные
  секции. Заголовки экранов короткие или отсутствуют там, где экран — это фото.
- Иконки — нейтральные (Material Symbols), без «волшебной палочки» для главного действия.
- Дизайн-токены в `ui_kit`: цвета (light/dark, контраст ≥ 4.5:1), типографика (масштабируемая), отступы 4/8/12/16/24, радиусы, длительности анимаций.
- Тёмная тема — по системной настройке; переключение в настройках.
- Edge-to-edge на Android 15+ (target 36): корректные insets, жесты навигации.
- Иконка, цвета, голос бренда — [appendix/brand.md](appendix/brand.md); токены `ui_kit` берут значения оттуда.

## 9. Локализация

- `gen_l10n` + ARB, ключи в `snake_case`, описание контекста для каждого ключа (`@key.description`).
- Плюрализация ICU (`{count, plural, one{…} few{…} many{…} other{…}}`) — русский требует форм one/few/many.
- RTL: `Directionality`, зеркальные иконки, проверка на псевдолокали (R0.5).
- Weblate (бесплатный хостинг для libre-проектов) — с R0.5; языки на старте — en, ru (Q-08).
- Тексты лицензий моделей не переводятся (юридически значимы), к ним даётся переведённое резюме.
