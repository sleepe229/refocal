# 05. Инференс и оптимизация

## 1. Бэкенды

| Платформа | Основной | Fallback 1 | Fallback 2 | Позже |
|---|---|---|---|---|
| Android | ncnn + Vulkan (fp16 storage/arith) | ncnn CPU (NEON, fp16 storage, многопоток) | — | R1.4: ONNX Runtime + QNN EP (Snapdragon 8 Gen 2+, w8a8), отдельной загрузкой |
| iOS | Core ML, mlprogram fp16, `computeUnits = .all` (ANE) | Core ML `.cpuAndGPU` | ncnn CPU | — |

Обоснование и отклонённые альтернативы — [ADR-0001](adr/ADR-0001-inference-backends.md). Ключевые факты:

- NNAPI NDK API объявлен устаревшим в Android 15 [V] — не используется.
- ONNX Runtime на Android не имеет общего GPU-EP; QNN EP отстаёт по версиям (QNN-сборка 1.24.1 при основной 1.26.0) [V].
- ncnn + Vulkan — проверенный путь для Real-ESRGAN (realesrgan-ncnn-vulkan, Upscayl); GFPGAN конвертируется через pnnx.
- Core ML — единственный путь к ANE на iOS.

| NFR-PERF-022 | ncnn Vulkan pipeline cache сохраняется на диск между запусками | Should | R0.2 | Вторая загрузка быстрее первой ≥ 2× | — |

## 2. Лестница отказов

Каждый шаг генерирует событие `FALLBACK` и отображается в UI (FR-ENH-013).

| Шаг | Условие | Действие |
|---|---|---|
| 1 | Ошибка аллокации / `ENH_E_OOM` / memory pressure | Тайл ÷ 2 (512 → 256 → 128 → 64) |
| 2 | `VK_ERROR_DEVICE_LOST`, ошибка компиляции Core ML, сработал crash sentinel | Смена бэкенда: Vulkan → CPU; Core ML `.all` → `.cpuAndGPU` → `.cpuOnly` → ncnn CPU. Пара драйвер+модель в blocklist (на сессию; постоянно — при срабатывании sentinel) |
| 3 | NaN/Inf или неверный выход (fp16 переполнение, чаще на лицах) | Повтор в **Vulkan fp32** (если бэкенд не заблокирован; S3: исправен там, где fp16 даёт мусор, и в 2× быстрее CPU) → fp32 CPU → пропуск лица с предупреждением. Для `wrong_output` в бенчмарке пишется локальное правило `gpu_fp32` |
| 4 | Нехватка памяти даже при тайле 64 на CPU | Предложить пользователю понизить масштаб (4× → 2×) — **только с подтверждением** |
| 5 | Нет места на диске | Ошибка с указанием требуемого объёма |
| 6 | Иное невосстановимое | Код ошибки, понятное сообщение, «Сообщить» (лог без фото) |

Детали — [ADR-0016](adr/ADR-0016-fallback-crash-sentinel.md).

## 3. Тайлинг

| Параметр | Значение | Обоснование |
|---|---|---|
| Размер тайла (ядро во входных px; вход сети = T + 2·pad) | 128 (T0), 256 (T1), 256 (T2) | Баланс памяти и накладных расходов. **512 не используется** (S2): пик CPU 1.08 ГБ, ncnn Vulkan даёт локальные ошибки до 164/255 на формах 544², выигрыш всего 5–9% |
| Паддинг | 16 px (compact, подтверждено S2: швы ≤ 9/255, 66–75 дБ к проходу целиком), 24 px (x4plus — проверить `seam_metrics.py` в R0.5); reflect на краях изображения | Перекрывает рецептивное поле (compact: RF 34). Pad 8 уже даёт швы до 24/255 |
| Feather | **Выключен по умолчанию** для моделей с pad ≥ ½ рецептивного поля (S2: измеримого эффекта нет); включается флагом рецепта для моделей без такого запаса | — |
| Порядок | Растровый; полоса = один ряд тайлов | Потоковая запись полос, checkpoint по полосам |
| Конвейер | `prep` (CPU: вырезка, нормализация) → `infer` (GPU) → `post` (денормализация, бленд, запись) с очередями глубиной 2 | Скрывает CPU-работу за инференсом |
| Последний ряд/столбец | Тайл сдвигается внутрь изображения (не уменьшается), перекрытие обрабатывается feather | Фиксированная форма тайла |

Пример: вход 1024×768, тайл 128, pad 16 → 48 тайлов (8×6) по 160². На 8 Gen 3 NPU (w8a8) это ≈ 0.4 с для compact и ≈ 4 с для x4plus + ~30% на pre/post `[оценка]`.

## 4. Политика разрешений

| Тир | Макс. вход для 4× | Макс. длинная сторона выхода | Поведение при превышении |
|---|---|---|---|
| T0 | 0.5 МП (→ 8 МП) | 4096 | Диалог: «быстрый 2×» / только лица / уменьшить вход |
| T1 | 1 МП (→ 16 МП) | 8192 | Диалог: 2× / только лица |
| T2 | 3–6 МП (→ 48–100 МП потоково) | ~12000 | Диалог при > 100 МП |

- Вход ≥ 4 МП → Auto по умолчанию выбирает 2× или «только лица» (разумный выход и время).
- Выход никогда не собирается целиком в памяти: см. §5 и ADR-0004.
- Превью для UI — уменьшенная копия ≤ 2048 + пирамида тайлов 256 px для зума.

## 5. Бюджеты памяти по стадиям

Бюджет: `B = min(tier_cap, os_available × 0.6)`, потолки: T0 600 МБ, T1 1.0 ГБ, T2 1.8 ГБ.

Пример: вход 12 МП (4000×3000), 4× (выход 16000×12000 = 192 МП = 576 МБ RGB8 — **не помещается**), T1, compact SR, 1 лицо.

| # | Стадия | Пик памяти |
|---|---|---|
| 1 | Decode (RGB8) | 36 МБ |
| 2 | Orient (поворот) | +36 МБ на время поворота |
| 3 | Analyze (уменьшенная до 640 копия, YuNet) | ~5 МБ |
| 5 | RestoreFaces: веса fp16 177 МБ + активации fp16 ~0.4 ГБ (GFPGAN держит SFT-условия всех разрешений); патч лица ≤ 6 МБ; **модель выгружается после стадии** [S1, оценка для устройства] | ~600 МБ |
| 6 | SRBanded [S2, CPU]: T=128 — активации ncnn 62 МБ + две полосы 49 МБ + вход 36 МБ; T=256 — активации 184 МБ + полосы 98 МБ + вход 36 МБ; iGPU T=256 — RSS 354 МБ + GPU 149 МБ. x4plus — замерить (R0.5) | **212 МБ (T=128) / 383 МБ (T=256)** |
| 7 | BandStore: полоса 512 (T=128) или 1024 (T=256) выходных строк × 16000 × 3 = 24.6 / 49 МБ, до двух в работе (входит в стадию 6). Хранится **без сжатия**: LZ4 экономит 3.6% (S2) | входит в 6 |
| 8 | Превью ≤ 2048 (аккумулятор uint32; на uint16 — 18 МБ) | 37 МБ |
| 9 | Encode из BandStore: JPEG q92 2.2 с без SIMD (0.4 с с SIMD); PNG — zlib level 1–3 (level 6 — 63 с) | 1 полоса + ~10 МБ |
| — | Базовая память Vulkan-драйвера: 115–160 МБ (десктоп Intel), до 265 МБ (NVIDIA); на устройствах — замерить в S2b/S3b | — |

**Итог T1:** пик ≈ max(600, 200) МБ — в пределах 1 ГБ. На T0 (600 МБ) восстановление лиц по умолчанию выключено (NFR-PERF-003). На CPU-пути для face-моделей отключаются winograd/sgemm: −0.45 ГБ на расширенных копиях весов [S1]. Плюс Flutter `imageCache` (NFR-MEM-006).

**Методика учёта:** на устройствах с общей памятью бюджет считается как RSS + память GPU-аллокаций (Android: `dumpsys meminfo`, строки Graphics/GL mtrack; iOS: `phys_footprint` уже включает). В S2 память iGPU добавляла 84–339 МБ сверх VmRSS.

Лимиты ОС (ориентиры, Apple не публикует точных значений): iOS jetsam ~1.4 ГБ (3 ГБ RAM), ~2–2.5 ГБ (4 ГБ), ~3–3.5 ГБ (6 ГБ) [оценка сообщества]. Entitlement `com.apple.developer.kernel.increased-memory-limit` добавляется, но не учитывается в бюджете. Android — native heap ограничен только LMK; ориентир — `MemoryInfo.availMem`.

## 6. Тиры устройств

См. [ADR-0017](adr/ADR-0017-device-tiers.md).

### 6.1 Статическая классификация

| Сигнал | Источник |
|---|---|
| RAM | `ActivityManager.MemoryInfo.totalMem` / `ProcessInfo.physicalMemory` |
| SoC | `Build.SOC_MODEL` (API 31+), `Build.HARDWARE`; `utsname.machine` → таблица чипов Apple |
| GPU/драйвер | `VkPhysicalDeviceProperties` (vendor, device, driverVersion), версия Vulkan |
| Blocklist | Встроенный + из манифеста (`gpu_blocklist`) |
| Класс производительности | `Build.VERSION.MEDIA_PERFORMANCE_CLASS` (подсказка) |

### 6.2 Микробенчмарк

- При первом запуске (в фоне, не блокирует UI) и после обновления приложения/модели/драйвера/ОС.
- **Время:** compact SR на тайле 128, 1 прогрев + N = 5 прогонов. Бэкенды: GPU fp16 и CPU; GPU fp32 — только если fp16 не прошёл. Каждый бэкенд проверяется в отдельном процессе (Android: `:bench` service) с таймаутом; прогрев дольше 1 с → `too_slow`.
- **Корректность** (ловит драйверы, выдающие мусор без ошибки) — на встроенном эталонном тайле 160 → 640 **и на рабочем размере тайла тира** (S2: ncnn Vulkan ошибается на больших формах). Гейт:
  - форма выхода верна;
  - нет NaN/Inf (одиночный NaN проходит по PSNR, S3);
  - PSNR ≥ 35 дБ;
  - `bad_frac` ≤ 0.1% — доля 8-битных значений с ошибкой > 16 (ловит локальную порчу блока, S3).
- Не прошёл → `wrong_output`, локальное правило `gpu_fp32` (сначала fp32 на том же GPU) или `cpu`.
- Результат кэшируется по ключу `{app_ver, model_ver, driver_ver, gpu_device_id, os_build, gate_version}` в `benchmark_cache`, в формате отчёта `refocal-probe/1` ([S3](../spikes/S3.md)).
- Пользователь может переопределить тир/бэкенд в настройках (FR-SET-003).

### 6.3 Итоговые правила

```
backend = fastest(b for b in backends if b.status == ok and not blocklisted(b))   # не «GPU first»
t = backend.tile128_ms
tier = T0 if mem_total < 3.3GB or t > 80
       T2 if mem_total >= 7.0GB and t <= 25
       T1 otherwise
if t > 280: T0 + предупреждение «устройство медленнее бюджета T0»
# таблица SoC — только подсказка до первого бенчмарка
```

Пороги 25 / 80 / 280 мс и 3.3 / 7.0 ГБ выведены из NFR-PERF-001 и замеров S3 `[S3 десктоп; калибровка → S3b]`.

**Поправка (2026-10-17, S3b):** для GPU-бэкенда пороги T2 ≤ 55 мс и T1 ≤ 170 мс. Джоб на Vulkan идёт тайлами 256, они загружают GPU лучше 128-пиксельного тайла бенчмарка: на Galaxy S24 Ultra (Adreno 750) tile128 47 мс, а 1 МП → 4× — 3.1 с, то есть ~66 единиц tile128 вместо 140. Со старым порогом 25 мс флагман попадал в T1 (скрыты 8× и x4plus). CPU-пороги и нижняя граница T0 не меняются до замеров на других устройствах ([отчёт](../spikes/S3b.md)). Блокировка Vulkan сама по себе не означает T0: быстрый CPU или ANE может дать T1.

## 7. Квантизация

| Точность | Где | Условие |
|---|---|---|
| fp16 | По умолчанию на всех GPU/ANE-бэкендах; хранение весов на CPU | Паритет ≥ 35 дБ / LPIPS ≤ 0.02 |
| fp32 | CPU-fallback для лиц при NaN; слои с переполнением (mixed precision) | — |
| int8 (w8a8) | Только NPU-тир (R1.4); per-channel веса; первый/последний слой и upsampler в fp16 | QAT или PTQ + обязательный golden-гейт (ML-QNT-001) |

Размеры (ориентиры): general-x4v3 fp32 4.65 МБ / int8 1.25 МБ [V]; x4plus 63.9 / 16.7 МБ [V]; GFPGAN ~340 / ~170 / ~85 МБ [оценка].

Известный риск: PTQ на GAN-моделях даёт бандинг, сдвиг цвета, потерю текстур; QAT с int8-дружественной архитектурой — потеря < 0.1–0.2 дБ [V, MAI 2022]. Публичных замеров int8 для ESRGAN/GFPGAN нет — замер в R1.4.

## 8. Тепло и батарея

| Сигнал | Платформа | Реакция |
|---|---|---|
| `ProcessInfo.thermalState` = serious | iOS | Пауза 200–500 мс между тайлами, CPU-потоки −50% |
| `thermalState` = critical | iOS | Пауза джоба до `fair`, уведомление |
| `PowerManager.getThermalHeadroom(10)` > 0.9 или `THERMAL_STATUS_SEVERE` | Android (API 29/30+) | То же |
| Низкий заряд (< 15%) и не на зарядке | обе | Предупреждение перед пакетом; Auto предпочитает compact |
| Режим энергосбережения | обе | Предупреждение; ограничение пакета |

Ожидаемое замедление при длительной нагрузке на GPU — 30–50% после 1–3 минут `[оценка → S2b]` (десктоп не троттлит, время полосы стабильно ±1%).

## 9. Модели: загрузка и поставка

- Встроены: `det.yunet`, `sr.general-x4v3` (уровень денойза 0.5) fp16 — ≈ 3 МБ на платформу.
- Остальное — паки по запросу: Hugging Face (основной; CDN, HTTP Range) → GitHub Releases (зеркало, ≤ 2 ГБ на файл).
- Play Asset Delivery и iOS On-Demand Resources **не используются** (не кроссплатформенно, не работает для F-Droid и NC-паков; ODR, по сообщениям, устаревает).
- Загрузка: `background_downloader` (URLSession / WorkManager), докачка Range, проверка SHA-256 до использования, атомарный rename.

## 10. Perf-харнесс

- `refocal-cli bench` (desktop) и встроенный в debug/profile-сборку экран «Бенчмарк».
- Метрики: время на стадию, с/МП входа, пиковый RSS (Android `/proc/self/status` VmHWM; iOS `phys_footprint` из `task_vm_info`), тепловое состояние до/после, заряд.
- Экспорт в JSON; ночной прогон на устройствах матрицы → график трендов, алерт при регрессии > 10%.
- Требования к замеру — [02 §2](02-nfr.md#2-производительность-perf), тесты — TEST-PERF-*.

## 11. Blocklist GPU-драйверов

```json
{
  "gpu_blocklist": [
    {"vendor": "ARM", "device_regex": "Mali-G52.*", "driver_max": "r26p0",
     "models": ["face.*"], "reason": "fp16 NaN in modulated conv", "action": "cpu"},
    {"vendor": "ImgTec", "device_regex": "PowerVR.*", "models": ["*"], "action": "cpu"}
  ]
}
```

Семантика ([S3 §5](../spikes/S3.md)):
- `device_regex` — полное совпадение без учёта регистра;
- `driver_min`/`driver_max` — префиксное включительное сравнение после декодирования `driverVersion` по вендору (NVIDIA и Mesa подтверждены; Qualcomm, ARM, ImgTec — S3b);
- `os_*` — Android API level или версия iOS; `models` — glob по `<pack>@<версия>`;
- дополнительные поля: `id`, `platform`, `api_max`, действие `gpu_fp32`, верхнеуровневый список `gpu_blocklist_revoke`;
- локальные записи фиксируют точную версию драйвера, поэтому обновление драйвера их снимает;
- встроенный список сразу отправляет llvmpipe и SwiftShader на CPU. Записи Mali-G52 и PowerVR выше — пример, не проверены (S3b).

- Источники: встроенный список (сборка) + `gpu_blocklist` в подписанном манифесте (обновляется без релиза, но только при включённой пользователем проверке обновлений) + локальный (crash sentinel, провал бенчмарка).
- Наполнение — по результатам S3 и issue «плохой результат».
