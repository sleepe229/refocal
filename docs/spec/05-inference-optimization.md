# 05. Инференс и оптимизация

## 1. Бэкенды

| Платформа | Основной | Fallback 1 | Fallback 2 | Позже |
|---|---|---|---|---|
| Android | ncnn + Vulkan (fp16 storage/arith) | ncnn CPU (NEON, fp16 storage, многопоток) | — | R1.3: ONNX Runtime + QNN EP (Snapdragon 8 Gen 2+, w8a8), отдельной загрузкой |
| iOS | Core ML, mlprogram fp16, `computeUnits = .all` (ANE) | Core ML `.cpuAndGPU` | ncnn CPU | — |

Обоснование и отклонённые альтернативы — [ADR-0001](adr/ADR-0001-inference-backends.md). Ключевые факты:

- NNAPI NDK API объявлен устаревшим в Android 15 [V] — не используется.
- ONNX Runtime на Android не имеет общего GPU-EP; QNN EP отстаёт по версиям (QNN-сборка 1.24.1 при основной 1.26.0) [V].
- ncnn + Vulkan — проверенный путь для Real-ESRGAN (realesrgan-ncnn-vulkan, Upscayl); GFPGAN конвертируется через pnnx.
- Core ML — единственный путь к ANE на iOS.

| ID | Требование | Приоритет | Релиз | Критерий | Трассировка |
|---|---|---|---|---|---|
| NFR-PERF-020 | Бэкенды реализуют единый интерфейс `InferenceBackend`; пайплайн не знает о конкретном бэкенде | Must | R0.1 | Ревью; тесты пайплайна с mock-бэкендом | ADR-0001 |
| NFR-PERF-021 | Скомпилированные Core ML модели (`.mlmodelc`) кэшируются; повторная загрузка ≤ 1 с | Must | R0.1 | TEST-PERF-001 | S4 |
| NFR-PERF-022 | ncnn Vulkan pipeline cache сохраняется на диск между запусками | Should | R0.2 | Вторая загрузка быстрее первой ≥ 2× | — |
| NFR-PERF-023 | Одновременно в памяти — одна тяжёлая модель (face → выгрузка → SR) | Must | R0.2 | TEST-PERF-002 | ADR-0012 |

## 2. Лестница отказов

Каждый шаг генерирует событие `FALLBACK` и отображается в UI (FR-ENH-013).

| Шаг | Условие | Действие |
|---|---|---|
| 1 | Ошибка аллокации / `ENH_E_OOM` / memory pressure | Тайл ÷ 2 (512 → 256 → 128 → 64) |
| 2 | `VK_ERROR_DEVICE_LOST`, ошибка компиляции Core ML, сработал crash sentinel | Смена бэкенда: Vulkan → CPU; Core ML `.all` → `.cpuAndGPU` → `.cpuOnly` → ncnn CPU. Пара драйвер+модель в blocklist (на сессию; постоянно — при срабатывании sentinel) |
| 3 | NaN/Inf на выходе (fp16 переполнение, чаще на лицах) | Повтор в fp32 на CPU → пропуск лица с предупреждением |
| 4 | Нехватка памяти даже при тайле 64 на CPU | Предложить пользователю понизить масштаб (4× → 2×) — **только с подтверждением** |
| 5 | Нет места на диске | Ошибка с указанием требуемого объёма |
| 6 | Иное невосстановимое | Код ошибки, понятное сообщение, «Сообщить» (лог без фото) |

Детали — [ADR-0016](adr/ADR-0016-fallback-crash-sentinel.md).

## 3. Тайлинг

| Параметр | Значение | Обоснование |
|---|---|---|
| Размер тайла | 128 (T0), 256 (T1), 256–512 (T2) | Баланс памяти активаций и накладных расходов; фиксированные формы для ANE/QNN/ncnn |
| Паддинг | 16 px (compact), 24 px (x4plus); reflect на краях изображения | Перекрывает рецептивное поле — шов после обрезки паддинга незаметен |
| Feather | Линейный, 8 px выхода по линии перекрытия | Страховка от остаточных швов |
| Порядок | Растровый; полоса = один ряд тайлов | Потоковая запись полос, checkpoint по полосам |
| Конвейер | `prep` (CPU: вырезка, нормализация) → `infer` (GPU) → `post` (денормализация, бленд, запись) с очередями глубиной 2 | Скрывает CPU-работу за инференсом |
| Последний ряд/столбец | Тайл сдвигается внутрь изображения (не уменьшается), перекрытие обрабатывается feather | Фиксированная форма тайла |

Пример: вход 1024×768, тайл 128, pad 10 → ~80 тайлов. На 8 Gen 3 NPU (w8a8) это ≈ 0.4 с для compact и ≈ 4 с для x4plus + ~30% на pre/post `[оценка]`.

## 4. Политика разрешений

| Тир | Макс. вход для 4× | Макс. длинная сторона выхода | Поведение при превышении |
|---|---|---|---|
| T0 | 0.5 МП (→ 8 МП) | 4096 | Диалог: «быстрый 2×» / только лица / уменьшить вход |
| T1 | 1 МП (→ 16 МП) | 8192 | Диалог: 2× / только лица |
| T2 | 3–6 МП (→ 48–100 МП потоково) | ~12000 | Диалог при > 100 МП |

- Вход ≥ 4 МП → Auto по умолчанию выбирает 2× или «только лица» (разумный выход и время).
- Выход никогда не собирается целиком в памяти: см. §5 и ADR-0004.
- Превью для UI — уменьшенная копия ≤ 2048 + пирамида тайлов 256 px для зума.

## 5. Бюджеты памяти по стадиям

Бюджет: `B = min(tier_cap, os_available × 0.6)`, потолки: T0 600 МБ, T1 1.0 ГБ, T2 1.8 ГБ.

Пример: вход 12 МП (4000×3000), 4× (выход 16000×12000 = 192 МП = 576 МБ RGB8 — **не помещается**), T1, compact SR, 1 лицо.

| # | Стадия | Пик памяти |
|---|---|---|
| 1 | Decode (RGB8) | 36 МБ |
| 2 | Orient (поворот) | +36 МБ на время поворота |
| 3 | Analyze (уменьшенная до 640 копия, YuNet) | ~5 МБ |
| 5 | RestoreFaces: веса fp16 177 МБ + активации fp16 ~0.4 ГБ (GFPGAN держит SFT-условия всех разрешений); патч лица ≤ 6 МБ; **модель выгружается после стадии** [S1, оценка для устройства] | ~600 МБ |
| 6 | SRBanded: тайл 256 → вход ~1 МБ fp32, выход 1024²×3×4 ≈ 12–16 МБ; активации compact 10–40 МБ (x4plus 150–250 МБ) | ~200 МБ |
| 7 | BandStore: полоса 1024 строк × 16000 × 3 ≈ 49 МБ (две в работе) | ~100 МБ (входит в стадию 6) |
| 8 | Пирамида / превью | ~10 МБ |
| 9 | Encode из BandStore | ≤ 2 полос |

**Итог T1:** пик ≈ max(600, 200) МБ — в пределах 1 ГБ. На T0 (600 МБ) восстановление лиц по умолчанию выключено (NFR-PERF-003). На CPU-пути для face-моделей отключаются winograd/sgemm: −0.45 ГБ на расширенных копиях весов [S1]. Плюс Flutter `imageCache` (NFR-MEM-006).

Лимиты ОС (ориентиры, Apple не публикует точных значений): iOS jetsam ~1.4 ГБ (3 ГБ RAM), ~2–2.5 ГБ (4 ГБ), ~3–3.5 ГБ (6 ГБ) [оценка сообщества]. Entitlement `com.apple.developer.kernel.increased-memory-limit` добавляется, но не учитывается в бюджете. Android — native heap ограничен только LMK; ориентир — `MemoryInfo.availMem`.

## 6. Тиры устройств

См. [ADR-0017](adr/ADR-0017-device-tiers.md).

### 6.1 Статическая классификация

| Сигнал | Источник |
|---|---|
| RAM | `ActivityManager.MemoryInfo.totalMem` / `ProcessInfo.physicalMemory` |
| SoC | `Build.SOC_MODEL` (API 31+), `Build.HARDWARE`; `utsname.machine` → таблица чипов Apple |
| GPU/драйвер | `VkPhysicalDeviceProperties` (vendor, device, driverVersion), версия Vulkan |
| Blocklist | Встроенный + из манифеста (`gpu_blocklist`) |
| Класс производительности | `Build.VERSION.MEDIA_PERFORMANCE_CLASS` (подсказка) |

### 6.2 Микробенчмарк

- При первом запуске (в фоне, не блокирует UI) и после обновления приложения/модели/драйвера/ОС.
- Compact SR на тайле 128, N = 5 прогонов на каждом доступном бэкенде.
- **Проверка корректности:** выход сравнивается с эталонным тайлом (встроен в приложение), PSNR ≥ 35 дБ. Не прошёл — бэкенд помечается неисправным (ловит драйверы, выдающие мусор без ошибки).
- Результат кэшируется по ключу `{app_ver, model_ver, driver_ver, os_build}` в `benchmark_cache`.
- Пользователь может переопределить тир/бэкенд в настройках (FR-SET-003).

### 6.3 Итоговые правила

```
if blocklisted(gpu) or bench.gpu_failed: backend = CPU
tier = T0 if ram < 4GB or backend == CPU and bench.cpu_tile128_ms > 400
       T2 if ram >= 8GB and soc in T2_SOCS and bench.gpu_tile128_ms <= T2_THRESHOLD
       T1 otherwise
```

Пороги `T2_THRESHOLD`, `400 мс` — `[оценка → S1/S3]`.

## 7. Квантизация

| Точность | Где | Условие |
|---|---|---|
| fp16 | По умолчанию на всех GPU/ANE-бэкендах; хранение весов на CPU | Паритет ≥ 35 дБ / LPIPS ≤ 0.02 |
| fp32 | CPU-fallback для лиц при NaN; слои с переполнением (mixed precision) | — |
| int8 (w8a8) | Только NPU-тир (R1.3); per-channel веса; первый/последний слой и upsampler в fp16 | QAT или PTQ + обязательный golden-гейт (ML-QNT-001) |

Размеры (ориентиры): general-x4v3 fp32 4.65 МБ / int8 1.25 МБ [V]; x4plus 63.9 / 16.7 МБ [V]; GFPGAN ~340 / ~170 / ~85 МБ [оценка].

Известный риск: PTQ на GAN-моделях даёт бандинг, сдвиг цвета, потерю текстур; QAT с int8-дружественной архитектурой — потеря < 0.1–0.2 дБ [V, MAI 2022]. Публичных замеров int8 для ESRGAN/GFPGAN нет — замер в R1.3.

## 8. Тепло и батарея

| Сигнал | Платформа | Реакция |
|---|---|---|
| `ProcessInfo.thermalState` = serious | iOS | Пауза 200–500 мс между тайлами, CPU-потоки −50% |
| `thermalState` = critical | iOS | Пауза джоба до `fair`, уведомление |
| `PowerManager.getThermalHeadroom(10)` > 0.9 или `THERMAL_STATUS_SEVERE` | Android (API 29/30+) | То же |
| Низкий заряд (< 15%) и не на зарядке | обе | Предупреждение перед пакетом; Auto предпочитает compact |
| Режим энергосбережения | обе | Предупреждение; ограничение пакета |

Ожидаемое замедление при длительной нагрузке на GPU — 30–50% после 1–3 минут `[оценка → S2]`.

## 9. Модели: загрузка и поставка

- Встроены: `det.yunet`, `sr.general-x4v3` (уровень денойза 0.5) fp16 — ≈ 3 МБ на платформу.
- Остальное — паки по запросу: Hugging Face (основной; CDN, HTTP Range) → GitHub Releases (зеркало, ≤ 2 ГБ на файл).
- Play Asset Delivery и iOS On-Demand Resources **не используются** (не кроссплатформенно, не работает для F-Droid и NC-паков; ODR, по сообщениям, устаревает).
- Загрузка: `background_downloader` (URLSession / WorkManager), докачка Range, проверка SHA-256 до использования, атомарный rename.

## 10. Perf-харнесс

- `refocal-cli bench` (desktop) и встроенный в debug/profile-сборку экран «Бенчмарк».
- Метрики: время на стадию, с/МП входа, пиковый RSS (Android `/proc/self/status` VmHWM; iOS `phys_footprint` из `task_vm_info`), тепловое состояние до/после, заряд.
- Экспорт в JSON; ночной прогон на устройствах матрицы → график трендов, алерт при регрессии > 10%.
- Требования к замеру — [02 §2](02-nfr.md#2-производительность-perf), тесты — TEST-PERF-*.
