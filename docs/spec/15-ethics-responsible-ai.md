# 15. Ответственный ИИ

## 1. Позиция

Восстановление фото — это **интерпретация**, а не реконструкция: модели дорисовывают правдоподобные детали, которых в исходнике нет. Главный риск — незаметно «подменить» лицо человека или создать впечатление, что результат — подлинное фото. Проект открыто признаёт это и проектирует продукт вокруг честности.

## 2. Принципы

| Принцип | Как реализован | Требования |
|---|---|---|
| **Честность результата** | Никогда «оригинал»/«восстановлено»; формулировка «улучшено ИИ»; оригинал не перезаписывается | FR-EXP-008, 06 §6 |
| **Сохранение идентичности** | faceStrength 0.5 по умолчанию; ослабление на крупных лицах; CI-гейт ArcFace ≥ 0.95; ползунок fidelity для CodeFormer | FR-FACE-004/005/009, ML-FACE-001 |
| **Информированность** | Предупреждение при первом использовании лиц; раздел в «О приложении» и в описании сторов | FR-FACE-010 |
| **Маркировка** | IPTC DigitalSourceType в XMP по умолчанию; C2PA (1.3); отключение — с предупреждением | FR-META-004/005/006, COMP-REG-001/002 |
| **Приватность** | Всё на устройстве, без телеметрии | 07 |
| **Справедливость** | Оценка качества по подгруппам (тон кожи, возраст, очки, профиль), публикация в MODELS.md | ML-BIAS-001, TEST-ML-008 |
| **Подотчётность** | «Сообщить о плохом результате», публичный трекер, разбор жалоб | FR-REP-*, §5 |

## 3. Запрещённые сценарии и функции

Проект не реализует и не принимает PR (см. [12 §6](12-oss-governance-licensing.md#6-запрещённые-функции-политика-проекта)):

- face swap и перенос лиц;
- «раздевание», генерация наготы;
- изменение формы тела, бьютификация, изменение возраста, расы, пола;
- генерация лиц «с нуля»;
- отключение маркировки по умолчанию.

## 4. Дети и несовершеннолетние

- Приложение не определяет возраст и не делает специальной обработки.
- Golden-набор не содержит изображений детей (используются только изображения взрослых с подходящими лицензиями).
- Политика использования (в «О приложении» и README): «Не используйте результаты для обмана или выдачи изменённых изображений реальных людей за подлинные».

## 5. Процесс обработки жалоб

1. Issue `bad-result` (через FR-REP-*) → разметка категории: «чужое лицо», артефакты, цвет, bias, другое.
2. Ежемесячный разбор: повторяющиеся категории → задачи (пороги, маски, параметры по умолчанию, blocklist моделей).
3. Систематические проблемы с подгруппой → блокер релиза пака до исправления/документирования.
4. Сообщения о злоупотреблениях проектом/форками — по `CODE_OF_CONDUCT.md` и `SECURITY.md`.

## 6. Прозрачность в коммуникации

- Описание в сторах: «Обработка на устройстве. ИИ дорисовывает детали — результат может отличаться от реальности. Изображения маркируются как изменённые ИИ».
- README: раздел «Ограничения» (текст, номера, мелкие детали, крупные лица, bias моделей).
- MODELS.md: известные ограничения каждой модели.

## 7. Регуляторный контекст

- EU AI Act, ст. 50 — обязанности прозрачности для систем, генерирующих/изменяющих изображения (применяется с августа 2026). Применимость к некоммерческому open-source-инструменту не определена; проект соблюдает требования маркировки добровольно (COMP-REG-001).
- Политики сторов по AI-контенту — 08.
