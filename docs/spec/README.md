# Техническое задание: Refocal — on-device AI photo enhancer

**Refocal** — название и бренд: [appendix/brand.md](appendix/brand.md).

Open-source (Apache-2.0) кросс-платформенное приложение (Flutter, Android + iOS) для улучшения качества фотографий: апскейл, шумоподавление, восстановление лиц. Вся обработка — **на устройстве**, без сервера, аккаунтов и телеметрии.

| Дата | 2026-10-09 |

| Платформы | Android 10+ (API 29), iOS 16+ |
| Стек | Flutter + C++ native core (ncnn / Core ML) |
| Лицензия кода | Apache-2.0 |

## Конвенции

### Идентификаторы требований

Формат: `<ТИП>-<ОБЛАСТЬ>-<NNN>`.

| Тип | Значение |
|---|---|
| FR | Функциональное требование |
| NFR | Нефункциональное требование |
| ML | Требование к моделям и качеству |
| SEC | Безопасность |
| PRIV | Приватность |
| COMP | Соответствие платформам/регуляторике |
| A11Y | Доступность |
| TEST | Тестовое требование |
| OPS | Процессы, CI/CD, релизы |

Области: `ENH` (обработка), `FACE`, `CMP` (сравнение), `BATCH`, `HIST`, `PRE` (пресеты), `EXP` (экспорт), `META`, `MODEL`, `ONB` (онбординг), `SET`, `SHARE`, `REP` (репорт), `UX`, `PERF`, `MEM`, `SIZE`, `BAT`, `THERM`, `REL` (надёжность), `L10N`, `AND`, `IOS`, `FDR`, `REG`, `CI`, `REL`, `LIC` и др.

Требование оформляется строкой таблицы:

`ID | Формулировка | Приоритет | Релиз | Критерий приёмки | Трассировка`

- **Приоритет** — MoSCoW: Must / Should / Could / Won't (в этой версии).
- **Релиз** — R0.1 … R2.0 (см. [роадмап](13-roadmap-milestones.md)).
- **Критерий приёмки** — измеримый, проверяемый тестом или ревью.
- **Трассировка** — ссылки на ADR и TEST-*.

### Модальность

- «**должно**» — обязательно (Must);
- «**следует**» — Should;
- «**может**» — Could.

### Значения, требующие подтверждения

Числа, полученные оценкой, а не замером, помечены `[оценка → Sx]`, где Sx — спайк, после которого значение фиксируется (см. [13](13-roadmap-milestones.md#m0--спайки)).

## Процесс изменения ТЗ

1. Изменение — через Pull Request в `docs/spec/`.
2. Изменение архитектурного решения — новый ADR со статусом `Proposed`, старый помечается `Superseded by ADR-XXXX`.
3. Удалять ID нельзя: требование помечается `~~зачёркнуто~~ (Deprecated, причина)`.
4. Изменение NFR-чисел требует ссылки на замер (perf-харнесс, отчёт спайка).
