# ADR-0012: Pipeline engine

- **Статус:** Accepted
- **Дата:** 2026-10-09

## Контекст

Нужен понятный, расширяемый пайплайн с контролем памяти и возобновлением.

## Решение

Линейный граф стадий (`Stage` с `estimate()`/`run()`), собираемый из рецепта:
`Decode → Orient → Analyze → DetectFaces → RestoreFaces → [Preprocess] → SRBanded (+FacePaste +StrengthBlend) → BandStore → Pyramid → Encode → Metadata`.
- Лица восстанавливаются **до** SR: кроп из входа, варп патча сразу в координаты выхода, вставка при записи полос.
- В памяти одна тяжёлая модель: face → выгрузка → SR.
- Сила: `lerp(lanczos_up(input), sr, strength)`; лицо: `lerp(px, patch, mask×faceStrength×perFace)`.
- Будущие стадии в фиксированных слотах: `ScratchDetect/Inpaint` до лиц, `Colorize` после SR (на низком разрешении с переносом хромы).

## Последствия

(+) Простота, предсказуемая память, resume по полосам. (−) Нет произвольных DAG (не нужны).

## Отклонённые альтернативы

- Произвольный DAG-движок: переусложнение. - Лица после SR на полном выходе: больше памяти.
