# ADR-0012: Pipeline engine

- **Статус:** Accepted
- **Дата:** 2026-10-09

## Контекст

Нужен понятный, расширяемый пайплайн с контролем памяти и возобновлением.

## Решение

Линейный граф стадий (`Stage` с `estimate()`/`run()`), собираемый из рецепта:
`Decode → Orient → Analyze → DetectFaces → RestoreFaces → [Preprocess] → SRBanded (+FacePaste +StrengthBlend) → BandStore → Pyramid → Encode → Metadata`.
- Лица восстанавливаются **до** SR: кроп из входа, варп патча сразу в координаты выхода, вставка при записи полос.
- В памяти одна тяжёлая модель: face → выгрузка → SR.
- Сила: `lerp(lanczos_up(input), sr, strength)`; лицо: `lerp(px, patch, mask×faceStrength×perFace)`.
- Будущие стадии в фиксированных слотах: `ScratchDetect/Inpaint` до лиц, `Colorize` после SR (на низком разрешении с переносом хромы).

## Поправка (2026-10-14, 0.0.3)

`StrengthBlend` выполняется при экспорте (`enh_export`), а не в `SRBanded`: BandStore хранит SR-результат с силой 1, экспорт смешивает его полосами с Lanczos-3 апскейлом входа. Причина — FR-ENH-005 и FR-EXP-007: ползунок силы меняется без повторной обработки, превью в UI — смешивание двух превью. Цена: при силе < 1 экспорт заново декодирует вход (вход должен существовать, как и для resume); при силе 1 вход не нужен. `FacePaste` остаётся в `SRBanded`.

## Поправка (2026-10-15, 0.2): лица

`DetectFaces`: YuNet 2023mar на копии ≤ 640 px (вход BGR 0..255, дополнение справа/снизу до 640×640), декодирование выходов как в OpenCV `FaceDetectorYN` (score = √(cls·obj), смещения ячейки, страйды 8/16/32, NMS 0.3, порог 0.7), лица меньше 16 px пропускаются, не больше 32. `RestoreFaces`: подобие по 5 точкам к шаблону FFHQ-512 (МНК), билинейный warp 512×512, face-модель по лестнице бэкендов; детектор и face-модель освобождаются до загрузки SR. `FacePaste` в `SRBanded`: каждая полоса результата смешивает восстановленные лица через обратное преобразование, маска растушёвана по краю кропа (24 px поля, 72 px перехода), вес = faceStrength × (0.5 для лиц > 512 px во входе, FR-FACE-009). При resume лица считаются заново (детерминированно). Цветокоррекция в LAB (FR-FACE-008) и регион (FR-FACE-006) — следующим шагом.

## Последствия

(+) Простота, предсказуемая память, resume по полосам. (−) Нет произвольных DAG (не нужны).

## Отклонённые альтернативы

- Произвольный DAG-движок: переусложнение. - Лица после SR на полном выходе: больше памяти.
