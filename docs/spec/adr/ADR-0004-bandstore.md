# ADR-0004: On-disk BandStore

- **Статус:** Accepted
- **Дата:** 2026-10-09

## Контекст

Выход до 192 МП (576 МБ RGB8) не помещается в память; нужны checkpoint/resume, повторный экспорт в разные форматы, зум результата.

## Решение

Выход SR пишется полосами (ряд тайлов) в `jobs/<id>/bands/NNNN.raw` (RGB8 **без сжатия**). Порядок записи: tmp → fsync → rename → fsync каталога, затем `checkpoint.json {band_idx, recipe_hash, model_sha, backend, tile}`. S2 проверил: 7 прогонов с `kill -9` дали побайтово одинаковый результат, теряется не больше одной полосы, затраты < 1% времени. LZ4 убран: экономит 3.6% размера ценой +0.4–0.9 с и +46 МБ буфера. Финальное кодирование и генерация пирамиды (тайлы 256 px WebP q80) читают BandStore потоково. Перед стартом проверяется свободное место (оценка + 20%).

## Последствия

(+) Resume после kill/фона; несколько форматов из одного прогона; HEIC через data provider; просмотрщик 1:1.
(−) Дисковый I/O и до ~600 МБ временного места; нужна очистка (NFR-SIZE-005).

## Отклонённые альтернативы

- Прямой поток в libjpeg: нет resume и второго формата.
