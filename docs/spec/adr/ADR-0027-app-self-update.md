# ADR-0027: Обновление приложения без своего сервера

- **Статус:** Accepted
- **Дата:** 2026-10-21

## Контекст

APK раздаётся только через GitHub Releases. F-Droid откроется не раньше 2027-01. Сейчас пользователь узнаёт о новой версии, только если сам зайдёт в репозиторий, и ставит её вручную через браузер и «Файлы». Для «простого пользователя» (06 §1) это значит, что он навсегда останется на первой версии.

Ограничения:
- **Своего сервера нет и не будет** (ADR-0020). Всё, что есть, — GitHub Releases, GitHub Pages и CI.
- **Сеть только по действию пользователя или по opt-in** (PRIV-NET-001). Прецедент — еженедельная проверка паков NET-3.
- **F-Droid не принимает приложения с собственным обновлением**: бинарник в F-Droid должен обновляться только через F-Droid.
- **Сборка воспроизводима и подписана ключом разработчика** (S8). F-Droid сверяет свою сборку `fdroid` с нашим APK.

## Решение

1. **Флейвор `github`** — это `fdroid` плюс модуль обновления. Тот же `applicationId` и тот же ключ подписи, поэтому можно переходить между GitHub- и F-Droid-сборкой без переустановки.
   - В `fdroid` и `play` модуль обновления не компилируется вовсе.
   - Релиз публикует два APK:
     - `refocal-<tag>-arm64-v8a.apk` — `fdroid`, имя не меняется: на него указывает `Binaries:` рецепта `tools/fdroid/io.github.refocal.app.yml`;
     - `refocal-<tag>-github-arm64-v8a.apk` — сборка с обновлением, на неё ведут README и сайт.
   - Пользователь, однажды поставивший `fdroid`-APK из GitHub, обновляется вручную или через F-Droid.
2. **Описание обновления — `app-update.json` + `app-update.json.minisig`** в релизе `app-latest` (перезаписывается) и на GitHub Pages.
   - Поля: `versionCode`, `versionName`, `channel` (`stable` | `beta`), `url` (основной и зеркало), `size`, `sha256`, `minSdk`, `notes` (en/ru, из `fastlane/.../changelogs/<versionCode>.txt`), `published`.
   - Подписывает CI в `release.yml` после того, как мейнтейнер опубликует черновик релиза. Отдельная пара minisign: ключ U в секретах CI, запасной ключ у владельца офлайн. Оба публичных ключа вшиты в приложение.
   - Используются инструменты ADR-0011 и проверка подписи в ядре (ADR-0021). `versionCode` должен расти — это защита от отката.
3. **Проверка.**
   - Общий переключатель «Проверять обновления» (FR-SET-005) теперь отвечает и за паки, и за приложение. Сетевой запрос NET-6.
   - Переключатель предлагается один раз, после первого сохранённого результата, одним вопросом без жаргона. Это opt-in, по умолчанию выключено.
   - Проверка раз в 7 дней через WorkManager, только по безлимитной сети. Кнопка «Проверить сейчас» в «О приложении» — это действие пользователя, ей переключатель не нужен.
4. **Скачивание и проверка файла.**
   - APK скачивается в фоне (NET-7, Range-докачка), во внутренний каталог приложения.
   - Проверяются размер и SHA-256 из подписанного `app-update.json`.
   - Подпись APK сверяет сама система: обновление чужим ключом PackageInstaller отклонит.
5. **Установка.** Через `PackageInstaller` session:
   - **Android 12+:** `setRequireUserAction(USER_ACTION_NOT_REQUIRED)`. Без вопроса установка проходит, когда установщиком записано само приложение.
   - **Android 14+:** дополнительно `setRequestUpdateOwnership(true)`.
   - **Первое обновление** после установки из браузера подтверждает сам пользователь: разрешение «Установка неизвестных приложений» для Refocal и системный диалог. Последующие проходят без вопроса [R — проверить на устройстве Android 12, 14 и 16].
   - **Ставим только когда приложение свободно:** нет работы в очереди и в обработке.
   - Иначе показываем полосу «Новая версия готова — Обновить», а установка ждёт конца очереди. Незавершённая работа и так переживает перезапуск (ADR-0004), но процесс посреди обработки не убиваем.
6. **После обновления** приложение открывается само, если пользователь нажимал «Обновить». Один раз показывается «Что нового» — текст из `notes`.
7. **Каналы.** `stable` по умолчанию. `beta` (pre-release) включается в «Дополнительно».
8. **Модели.** Обновления установленных паков (FR-MODEL-008) идут под тем же переключателем и тоже скачиваются в фоне по безлимитной сети. Переключение на новую версию пака происходит атомарно, между работами.

## Последствия

(+) Никакого сервера: GitHub Releases, Pages и CI. Пользователь GitHub-сборки обновляется одним нажатием, а со второго обновления — без вопросов. F-Droid получает чистую сборку без модуля обновления.

(−) Появляется третий флейвор: в релизе два APK, а в CI проверяются оба (размер, подпись, отсутствие GMS).
- Нужно разрешение `REQUEST_INSTALL_PACKAGES` (только в `github`).
- Нужна ещё одна пара ключей.
- GitHub видит IP при проверке — как у NET-3.
- iOS этим путём не обновляется: там App Store и TestFlight (Q-06).

## Отклонённые альтернативы

- **Свой сервер или VDS:** против ADR-0020, его надо сопровождать.
- **Только уведомление со ссылкой на браузер:** не «бесшовно», пользователь теряется в «Файлах».
- **Модуль обновления в `fdroid`, выключаемый по источнику установки:** F-Droid не примет код самообновления в своей сборке, а флаг сборки сломал бы воспроизводимость.
- **Obtainium как единственный путь:** хорош для опытных (README), но это ещё одно приложение и настройки.
- **GitHub API `releases/latest` без подписи:** нет защиты от подмены и отката, лимит 60 запросов в час на IP. Подписанный статический файл надёжнее.
