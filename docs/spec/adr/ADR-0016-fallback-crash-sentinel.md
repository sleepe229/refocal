# ADR-0016: Fallback ladder and crash sentinel

- **Статус:** Accepted
- **Дата:** 2026-10-09

## Контекст

GPU-драйверы падают (SIGSEGV, не перехватывается) или выдают мусор; память ограничена.

## Решение

- Лестница: тайл÷2 → смена бэкенда → fp32 CPU для лица → пропуск лица → понижение масштаба с подтверждением → ошибка. Каждый шаг — событие `FALLBACK` в UI.
- Crash sentinel: перед GPU-стадией атомарно (tmp + fsync + rename) пишется `sentinel.json` с ключом `vendor:device:driverVersion|<pack>@<версия>`, после стадии — удаляется. Одна запись на стадию, а не на тайл. Политика при обнаружении на старте (проверена end-to-end в [S3](../../spikes/S3.md)):
  - Android API 30+: причина прошлого выхода берётся из `ApplicationExitInfo`. `REASON_CRASH_NATIVE`/ANR → блокировка сразу; `LOW_MEMORY`/`USER_*` → не учитывается.
  - Иначе (iOS, API 29): первое срабатывание → карантин на CPU на одну сессию, второе подряд → постоянная блокировка.
  - Успешная стадия сбрасывает счётчик.
- Бенчмарк с проверкой корректности ловит «тихий мусор» (ADR-0017).
- Программные Vulkan-устройства (`VkPhysicalDeviceType` CPU: SwiftShader, llvmpipe) никогда не выбираются: они медленнее CPU-бэкенда (S3), а в эмуляторе Android подвешивали джоб.
- Причина прошлого выхода передаётся ядру полем `enh_session_config.previous_exit` (`native_crash` / `os_kill` / NULL) из `ApplicationExitInfo` (Android 11+); на iOS — NULL, работает политика повторных срабатываний.

## Последствия

(+) Нет повторяющихся падений. (−) Ложные срабатывания sentinel при убийстве процесса ОС во время GPU-стадии — смягчение: blocklist только после 2 срабатываний подряд с одинаковым ключом.

## Отклонённые альтернативы

- Ничего не делать: повторяющиеся крэши, плохие отзывы.
