# ADR-0020: Build flavors and telemetry

- **Статус:** Accepted
- **Дата:** 2026-10-09

## Контекст

F-Droid запрещает проприетарные зависимости и неявный трекинг; проекту нужна диагностика.

## Решение

- Android-флейворы `play` и `fdroid` (без GMS/Firebase/ML Kit/Sentry, без `ModuleDependencies`). iOS — один таргет + Share Extension.
- Телеметрии нет. Локальный ротируемый лог ≤ 5 МБ (без путей к фото и GPS) с экспортом пользователем.
- Отчётов о падениях нет (ни opt-in, ни по умолчанию): у проекта нет серверов, а self-hosted GlitchTip требует поддержки инфраструктуры. Диагностика: экспорт локального лога пользователем + агрегированные данные платформ (Play Vitals / App Store Connect), если приложение публикуется в сторах. Решение пересматривается после 1.0 (Q-09).
- Все сетевые вызовы — только по действию пользователя; полный список — 07 §6.
- Flutter SDK закреплён git-сабмодулем (воспроизводимые сборки).

## Последствия

(+) F-Droid без анти-фич Tracking; «Data Not Collected» во всех декларациях; нечего поддерживать на сервере. (−) Меньше данных о падениях — компенсируется логами от пользователей, бета-тестерами и данными платформ.

## Отклонённые альтернативы

- Firebase Crashlytics: проприетарно, трекинг.
- Opt-in `sentry_flutter` → self-hosted GlitchTip: требует сервер и его сопровождение; отложено.
