# ADR-0017: Device tiers and benchmark

- **Статус:** Accepted
- **Дата:** 2026-10-09

## Контекст

Устройства отличаются на порядки по RAM, GPU и драйверам.

## Решение

Три тира T0/T1/T2 (см. 02 §1, 05 §6): статическая классификация (RAM, SoC, Vulkan/драйвер, blocklist, чип Apple) + микробенчмарк с проверкой корректности (PSNR ≥ 35 дБ к эталону) при первом запуске и после обновлений. Кэш по `{app_ver, model_ver, driver_ver, os_build}`. Ручное переопределение в настройках.

## Поправка (2026-10-21, 0.8.2): tier_min — не запрет

`tier_min` пакета в манифесте — класс скорости, на котором модель работает в бюджете
NFR-PERF-001, а не ограничение. Бета-тестер на телефоне T1 переключил тир на T2 вручную, и
модель «Качество» (`sr.x4plus`, T2) отработала нормально, а приложение её не давало. Теперь
пакет выше тира устройства не скрывается и не запрещается: предложение скачать его говорит
«будет медленно» (если манифеста ещё нет — отдельным вопросом после его загрузки), дальше
модель доступна как любая установленная. Авто по-прежнему выбирает по тиру устройства
(02 §1): медленную модель включает только сам пользователь. Тайлы, бюджет памяти и
фолбэк после сбоя (ADR-0016) остаются по тиру устройства, так что на слабом телефоне
медленная модель идёт малыми тайлами.

## Последствия

(+) Предсказуемый UX на любом устройстве. (−) Поддержка таблицы SoC и порогов.

## Отклонённые альтернативы

- Только статика: не ловит плохие драйверы. - Только бенчмарк: долго и шумно.
