# ADR-0014: Scale strategy

- **Статус:** Accepted
- **Дата:** 2026-10-09

## Контекст

Пользователю нужны 1×/2×/4×/8×, а модели — ×4.

## Решение

- 4×: модель x4.
- 2×: x4 + area-downscale при выдаче полосы; «быстрый 2×» на T0: вход ×0.5 → x4.
- 1×: x4 + downscale ×4 (денойз/восстановление без увеличения).
- 8×: x4 → x4 → ↓2; только вход ≤ 1.5 МП и T2.
- RealESRGAN_x2plus — опциональный пак для T2 (позже).

## Поправка (2026-10-20): эффективное разрешение

Масштаб задаёт размер результата, но не разрешение, на котором работает SR: размытый снимок
обрабатывается с входа, уменьшенного до его эффективного разрешения (`pre_down`), с
ресемплингом к тому же размеру выхода — см. [ADR-0025](ADR-0025-effective-resolution.md).

## Последствия

(+) Один набор моделей. (−) 2×/1× тратят вычисления x4: по S2 обычный 2× стоит 100% времени 4×, «быстрый 2×» — 25% (35 против 140 с на CPU для 12 МП). Поэтому быстрый 2× предлагается по умолчанию для входа ≥ 8 МП на T0/T1.

## Отклонённые альтернативы

- Отдельные x2/x1 модели для всех тиров: больше паков и конверсий.
