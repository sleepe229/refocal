# ADR-0011: Model packs and signed manifest

- **Статус:** Accepted
- **Дата:** 2026-10-09

## Контекст

Модели весят до ~190 МБ, часть под NC-лицензиями; нужна безопасная, кроссплатформенная, F-Droid-совместимая доставка.

## Решение

- Пак — версионированная единица (`id@semver`) с файлами под платформу/бэкенд, лицензией, IO-спецификацией, eval, provenance.
- Источник истины — `manifest.json` + `manifest.json.minisig` (minisign/Ed25519). В приложение вшиты 2 публичных ключа (ротация). `serial` монотонно растёт (защита от отката). Подпись проверяется до парсинга.
- Загрузка: Hugging Face → GitHub Releases (зеркало), HTTP Range, SHA-256, атомарный rename.
- NC-лицензии — явное согласие, сохраняется в `consents`.
- Офлайн-импорт `.rfpack` (zip + подписанный манифест).
- Встроены только YuNet и `sr.general-x4v3` fp16 (≈3 МБ).

## Поправка (2026-10-15, 0.2)

- **Ключи (решение владельца):** две пары minisign. Ключ A подписывает в CI (секрет `MODELS_MINISIGN_KEY`, workflow `models.yml`), ключ B хранится у владельца офлайн для ротации; оба публичных ключа — в `tools/models/keys` и в приложении (`manifestKeys`, тест сверяет).
- **Хостинг:** пока только GitHub Releases: файлы паков — ассеты релизов `model-<id>-v<N>` (вместе с текстом лицензии), манифест — релиз `models` (`manifest.json` + `.minisig`). Hugging Face добавится вторым URL в `urls` без изменения кода. Репозиторий открыт (2026-10-16): приложение скачивает их без токена.
- **Манифест в git:** `tools/models/manifest.json` — тот самый файл, что подписывается (ревью в PR); `check_manifest.py` проверяет схему, рост `serial` и каждый файл на каждом зеркале перед подписью. Паки устанавливаются в `AppSupport/models/<id>/` (как ищет ядро), версия — в `model_packs`.
- **Проверка в приложении:** подпись проверяется ядром (ADR-0021) до разбора; разбор строгий (лишние поля, не-https, пути в именах файлов — отказ); `serial` ниже принятого или тот же с другим содержимым — откат, отказ. Загрузка — HTTP Range с продолжением, зеркала по порядку, размер и SHA-256 каждого файла, установка одним rename. Согласие — на конкретный текст лицензии (его SHA-256 из манифеста), текст скачивается и проверяется перед показом.
- `.rfpack` (офлайн-импорт) — следующим шагом.

## Поправка (2026-10-16, 0.2): `.rfpack`

- **Формат:** zip, имена записей — плоские (`[A-Za-z0-9._-]`): `manifest.json` — манифест той же схемы с одним паком (serial и даты — как у сетевого), `manifest.json.minisig` — его подпись ключом A (или B), `license.txt` — текст лицензии (SHA-256 = `license.text_sha256`), файлы пака по их `path`. Собирает `tools/models/make_rfpack.py`; `models.yml` публикует `<id>-<version>.rfpack` в релиз `models` рядом с манифестом.
- **Разбор архива — в ядре** (`enh_rfpack_extract`, ABI 4; SEC-INP-005): при каждом вызове проверяется весь central directory — плоские имена (нет `..`, абсолютных путей, каталогов), только обычные файлы (нет симлинков), без шифрования и ZIP64, без дубликатов и перекрывающихся данных, ≤ 2 ГБ распакованного и коэффициент ≤ 100; извлекается одна запись не больше лимита вызывающего, с проверкой CRC-32 и размера. TEST-SEC-005 — `test_rfpack`, фаззинг — `fuzz_zip`.
- **Порядок в приложении:** извлекаются только манифест и подпись → подпись проверяется до разбора → строгий разбор, ровно один пак, есть файлы для платформы → версия не ниже установленной (иначе откат) → текст лицензии сверяется с манифестом и показывается для согласия (ADR-0022) → каждый файл извлекается не больше своего размера и сверяется по SHA-256 → установка тем же атомарным rename. Принятый сетевой манифест не меняется.

## Последствия

(+) Малый размер приложения, лицензионная чистота бандла, офлайн-сценарий. (−) Нужна инфраструктура подписи и процедура хранения ключа.

## Отклонённые альтернативы

- Всё в бандле: размер, NC в сторах. - Play Asset Delivery / ODR: не кроссплатформенно, не для F-Droid.
