# ADR-0010: System pickers and inbox copies

- **Статус:** Accepted
- **Дата:** 2026-10-09

## Контекст

Политика Play (с 05.2025) запрещает широкий доступ к медиа для таких приложений; URI пикеров могут истечь, а фону и очереди нужен стабильный файл.

## Решение

- Ввод только через Android Photo Picker (fallback `ACTION_OPEN_DOCUMENT`) и iOS PHPicker — без разрешений на чтение.
- Выбранный файл копируется в `AppSupport/inbox/` (дедуп по SHA-256). Квота по умолчанию 1 ГБ / 7 дней, очистка после экспорта, если не включено «Хранить для повторной обработки».

## Поправка (2026-10-15, 0.0.5): дедупликация (FR-IMP-004)

Копия называется `in-<sha256>.<ext>`: хеш считается во время копирования (без второго чтения), во временный `in-<uuid>.part`; если файл с таким именем уже есть, новая копия отбрасывается и возвращается существующая (HEIC на Android 10: `in-<sha256>.png`). Отдельная колонка `assets.sha256` из 07 §3 не нужна: путь уникален и уже содержит хеш. Одна копия может служить редактору, очереди и истории сразу, поэтому копию освобождает только `JobStore.releaseInput`, который учитывает каталоги джобов и ссылки очереди (`otherInputs`); прямое удаление файлов inbox запрещено (кроме старта, когда ничего не открыто, и «Хранилища», которое пропускает используемые).

## Последствия

(+) Соответствие политикам, устойчивость очереди. (−) Дополнительное место и I/O.

## Отклонённые альтернативы

- `READ_MEDIA_IMAGES`: отклоняется политикой Play. - Работа по URI без копии: ломается в фоне.
